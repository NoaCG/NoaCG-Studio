Getting started

NoaCG Studio makes broadcast graphics in the browser: lower thirds, scoreboards, tickers, quiz boards and countdowns. You make a graphic, then put it on air in the system your studio already uses.

Three ways to start
  1. A template. Pick a design from the catalog, then set its text, colors and logo. Open the studio →
  2. Your own design. Name the layers in Illustrator, save an SVG, import it and choose what it does. Import an SVG → or get the SVG examples →
  3. Your coding agent. Use Claude Code or Codex with the NoaCG CLI. Describe the graphic you want, and it appears in your NoaCG library. Set up your agent →

Then put it on air:

  • OBS and vMix show a graphic as a browser source.
  • CasparCG: the playout dashboard loads it there through NoaCG Bridge.

Graphics

Draw your graphic in Illustrator, Figma or Inkscape and import it as an SVG. Every text layer becomes a field the operator can retype. The layer names tell NoaCG what kind of graphic it is, so a scoreboard gets score buttons and a quiz gets quiz buttons.

Pick a type to see how to lay it out:

  • Scoreboard - two teams and two scores.
  • Quiz - a question and two to six answers.
  • Live vote - options with bars that grow as the audience votes.
  • Countdown - a clock that counts down to zero.
  • End credits - roles and names.
  • Ticker - a tag and a story line.

Any other graphic needs no special names. Its text layers become fields and that is all. A title, a name tag and the credits each still name their texts one way, listed under Layer names.

Import an SVG

  1. Open the studio and choose Import graphic. No account is needed until you publish a production.
  2. Set Project format first. The default is 16:9, 1920×1080, 25 fps. It locks once your file is in, with the message "Remove the current artwork before changing its authored canvas".
  3. Drop your SVG. NoaCG shows the size, how many text layers it found and which fonts the file uses. If it found fewer text layers than you drew, some text was exported as outlines. To try it before you draw your own, use name-tag.svg.
  4. Check the Fields step. Every ticked layer is a field the operator types into, labelled with your layer name. Rename a label here if you need to. What it does shows the type NoaCG found from your layer names. You can change it and pick the layers yourself.
  5. Choose how the graphic comes on and goes off in Animation.
  6. In Finish, name the graphic and choose Add to the production or Export it. Both save it to your library. Skip to finish in the footer of any earlier step brings you straight here, keeping the choices you have not made at their defaults.

On air

Add to the production takes you to the production with your graphic in the rundown. Press Take to put it on air. Type new text, then press Update to send it. Until you do, the panel says "1 change not on air yet". Out takes the graphic off. To get the picture into OBS, vMix or CasparCG, see the playout dashboard.

Prepare the SVG file

  • Give it a size. Use a 1920×1080 artboard with a transparent background and draw the graphic where it sits on screen, so a lower third goes at the bottom of that artboard. In Illustrator tick Use Artboards when you save the SVG, or the file is cut down to the drawing. A smaller artboard imports as a floating object that you place in the wizard.
  • Keep text as text. Do not convert text to outlines, because outlined text cannot be edited.
  • Name your layers. The name is the label the operator sees. For the types below it is also how NoaCG finds each part.
  • Embed pictures. Linked pictures are removed, because an exported graphic has to play without a network.
  • No animation or scripts. SVG animation, scripts and <foreignObject> are removed. Add motion in the Animation step.

Fonts

NoaCG lists every font the file uses. For each one it uses a bundled font, offers the same family from Google Fonts, or takes a font file you upload. The font is embedded in the graphic, so it plays offline. If nothing matches, you get a warning and the graphic uses a fallback font.

Layer names

Layer names in 30 seconds
  • Three layers, top of the Layers panel first: Text is what the operator types, Moments is what NoaCG shows or moves, Board stays as drawn. No moments, no Moments layer.
  • Name each text for what it is, the row last after a space: Question, Answer A, Team 1, Score 1. A title is Title and Subtitle, a name tag Name and Role, credits Heading and Credits.
  • A moment is a hidden group, with its row where it has one: Selected A, Flash 1, Full time. A bar is drawn at full length and left visible: Bar 1.
  • On the Board the background is Panel, a plate under a text is that text's name plus box (Question box, Answer box A, Score box 1), and fixed words start with static: (static:Letter A).
  • Anything else on the Board is decoration with any name. Every name is English. Save with File > Save a Copy > SVG.

Every graphic type uses the same three layers and the same way of naming what is in them. Learn it once and a quiz, a scoreboard and a vote are the same job. The rest of this page is the long version.

To start from a working file, download the SVG examples: a title, a lower third, a quiz, a scoreboard, a countdown, a ticker and rolling end credits, each as an Illustrator file and as the SVG it saves, with a short README.

The three layers

  • Text holds what the operator types. One text object per field, named for what it is: Question, Team 1.
  • Moments holds what NoaCG shows, hides or moves. A hidden group for each moment, such as Selected A or Full time, and a bar drawn at its full length, such as Bar 1.
  • Board holds what stays as drawn: the panel, the row plates, the letters and the labels.
  • A graphic with nothing to show or hide, such as a title, a name tag or the credits, has only Text and Board. Illustrator leaves an empty layer out of the SVG anyway.

Names on the Board

  • The background is Panel.
  • A plate under a text is that text's name plus box, with the row last: Question box, Answer box A, Score box 1. The wizard lists each plate by that name, so the plate and its text read as a pair.
  • Fixed words start with static:, as in static:Letter A.
  • Anything else is decoration and can have any name, like Edge or Rule.

Titles, name tags and credits

  • A title has Title and Subtitle.
  • A name tag has Name and Role. One name tag serves every person on the show: the operator retypes it.
  • Credits have Heading and Credits. Credits is one text holding the whole list, never a text per name.

A name is a word and a row

  • The word says what the layer is. The row is one letter or one number, last, after a space: Answer A, Score 1, Winner 2. A quiz counts in letters, because the letters are drawn on the board. Everything else counts in numbers.
  • Layers with the same row belong together. Answer B, Selected B, Correct B and Wrong B are all answer B.
  • A moment is a group that you hide in your design app. A hidden shape on its own is not found, so put it in a group, even a group of one. Text inside a hidden group is drawing, not a field.
  • A text that stays as drawn starts with static:, as in static:Letter A. A text that is a single letter, like the A on a quiz row, starts unticked whatever it is called.
  • The spelling does not matter, the words do. Capitals, spaces, underscores and dashes are all the same to NoaCG. So Answer A, answer_a and ANSWER-A are one name. AnswerA is Answer A too, and Score1 is Score 1.
  • The synonyms in the table below work too. The common words also work in Finnish, Swedish, German and Spanish: Antwort A, Puntos 1. The three layers can be called Text, Moments and Board in your own language, because NoaCG reads the names inside them. The examples use one spelling so that you can copy it.
  • In Illustrator, name each text object (double-click its row), or put it alone in a layer with the name: a text inside a layer called Question is Question. Four unnamed texts inside a layer called Answers are all Answers, and no type is found. Save the file with Save a Copy as above, because Export As leaves hidden layers out.
  • When the names fit a type, the wizard picks that type in What it does and fills in every layer. When a name does not fit, pick that layer from the list yourself.

Names for any graphic

  • static: at the start of a text layer's name, as in static:Heading, keeps the text as drawn. It is not an operator field.
  • f: at the start of a picture's name, as in f:Logo, makes it a field the operator can swap. Pictures without it start unticked.
  • Text drawn as a plain number, such as 84, becomes a number field with + and − buttons.
  • Text drawn as a time, such as 05:00, can become a countdown.
  • Give every layer its own name. If two layers are both called Bar, the second one becomes Bar 2.
  • Panels, lines, gradients and masks stay exactly as drawn.

When the operator types more than fits, NoaCG first uses the room in the shape behind the text, then wraps it onto a new line, then makes it smaller. Nothing is cut off.

Credits: one pasted list

End credits are one text layer named Credits, never a layer per name. The operator pastes the whole list into one box.

  • A line ending in : is a title, and the lines under it are its names. Director: Anna Ahonen on one line is the same thing.
  • A tab from a spreadsheet works in place of the colon.
  • A blank line starts a new section.

What you type into the layer in Illustrator is the sample, and it is how you style the roll. The first line ending in : is what every title will look like. The line under it is what every name will look like.

On Take the list rolls from the bottom of the frame to the top, at the Scroll speed the operator sets. At 100 that is about thirty lines in thirty seconds. Draw a plate named Credits box and the roll runs inside it.

Scoreboard

Two team names and two scores. The operator adds a point with one press.

Layer names

  • Team 1 and Team 2: text. Required.
  • Score 1 and Score 2: text, drawn as a plain number such as 2. Required.
  • Flash 1 and Flash 2: hidden group. Shows for a moment when that team scores. Optional.
  • Full time: hidden group. Shows at the end of the game. Optional.

Up to eight teams: Team 3, Score 3 and so on. The example draws the word GOAL inside each flash, but the layer is called Flash because a point is not always a goal.

Buttons

  • +1 and −1 for each team. +1 also shows that team's Flash layer.
  • Clear flash hides the Flash layer again.
  • Full time shows the Full time layer.
  • New game sets every score to 0.

The operator can also type any score straight into its field.

Quiz

A question and two to six answers. The operator selects an answer, locks it in and reveals the correct one.

Layer names

  • Question: text. Required.
  • Answer A, Answer B and on to Answer F: text. At least two. Required.
  • Selected A: hidden group. Shows on the answer the operator picks. Optional.
  • Correct A: hidden group. Shows on the correct answer at the reveal. Optional.
  • Wrong A: hidden group. Shows on every other answer at the reveal. Optional.
  • Locked in: hidden group. Shows once the answer is locked in. Optional.

Draw the same three for every answer: Selected B, Correct B and so on. A moment you do not draw gets NoaCG's own highlight. The letters on the rows are static:Letter A and so on, so they stay as drawn.

Buttons

  1. Set Correct answer before the show. It changes nothing on screen.
  2. Select answer highlights the letter in Selected answer. Press it again with another letter to change the pick.
  3. Lock it in makes the pick final.
  4. Reveal correct shows the right answer. It sends the letter in Correct answer with it, so a key you fix during the show is the one that lights up, even if you did not press Update.

Reveal choice stays greyed out on the road above. It is for keeping the pick secret: choose the letter in Selected answer, press Update, then Lock it in without pressing Select answer. The board shows it is locked but not which answer. Reveal choice then shows the pick, and Reveal correct works as before.

Live vote

The audience votes on their phones at your join link, and the bars grow with the count.

Layer names

  • Option 1, Option 2 and on to Option 8: text. At least two. Required. The vote writes each option's wording here.
  • Bar 1, Bar 2 and so on: a rectangle drawn at full length. Full length is 100%. Required.
  • Question: text. Optional.
  • Percent 1 and so on: text. Shows that option's share. Optional.
  • Winner 1 and so on: hidden group. Shows on the winning row. Optional.
  • Total votes: text. Optional.
  • Vote badge: hidden group. Shows while voting is open. Optional.

The Bar layers are what make the wizard pick Live vote. A bar grows from its left edge. Draw it as a plain rectangle with square ends, because other shapes are stretched. Draw the empty track behind it as its own layer in Board, called Track 1 and so on, never Bar.

Buttons

  • Close voting stops the vote.
  • Show result shows the final figures.
  • Call the winner shows the Winner layer on the row that won.

You open the vote itself on the production's Audience tab. The counts reach the graphic as a cue that you still take to air.

Countdown

A clock that counts down to zero. The operator sets the length in minutes.

Layer names

  • One text layer drawn as a time, such as 05:00. Any name; the example calls it Clock. Required. Keep it the only text in the file shaped like a time.
  • Timer bar: a rectangle drawn at its full length. It shrinks as the time runs out. Optional.
  • Warning: hidden group. Shows in the last 10 seconds. Optional.
  • Paused: hidden group. Shows while the clock is paused. Optional.
  • Time up: hidden group. Shows at zero. Optional.

The wizard picks Countdown when the file has the time layer and at least one of the four named layers. With only the time layer, choose Countdown in What it does yourself.

The length

  • The operator types the length in minutes. 3 is three minutes and 0.5 is thirty seconds.
  • Do not type the time you want on screen. 2:30 is two minutes, not two and a half.
  • An empty field, or 0, counts five minutes.

Buttons

  • Take starts the count from the full length.
  • Pause holds the count and Start carries on from there.
  • Reset goes back to the full length and waits for Start.
  • Warn at (seconds) is a field that sets when Warning shows.

End credits

A heading and the whole list of credits. The operator pastes the list into one field.

Layer names

  • Credits: one text object holding the whole list, one line per credit. A line ending in a colon is a title, and the names go under it. Never one text per name: nobody knows in advance how many names a show has.
  • Heading: text. Optional.
  • Style the first title line and the first name line the way every title and every name should look.

There is no Moments layer because nothing shows or hides. Panel is the background and Rule is decoration.

A scrolling roll

The Credits text is one box for the whole roll, however many names a show has. On Take it rolls from the bottom of the frame to the top, at the Scroll speed the operator sets. Draw a plate named Credits box and the roll runs inside it.

What you type into the layer in Illustrator is the sample. The first line ending in : is what every title looks like, and the line under it is what every name looks like. The catalog credits designs read the same box, written like this: 

Director: Alex Rivera

Camera Operators:
Jonas Berg
Lena Fors
  • A colon ends a role. Everything else is a name.
  • Put a role and its name on one line, or put the role on its own line with the names under it.
  • A blank line starts a new section. # PRODUCTION is a department heading.
  • A tab works in place of the colon, so a paste from a spreadsheet works.

Ticker

A tag and a story line along the bottom of the screen.

Layer names

  • Kicker: text. The tag, such as SPORT.
  • Story: text. The headline.

Neither name is special. Both are fields, and there is no Moments layer because nothing shows or hides. Panel is the strip, and the kicker sits on its own plate, Kicker box.

A crawl

An imported ticker shows one story and does not move. For a crawl or a rundown of several stories, start from a ticker design in the catalog instead. It has one text box for the whole rundown:

  • A kicker on its own line applies to every line under it, until a blank line.
  • The colon needs a space after it, so 2:1 and 20:45 stay part of the story.

Pictures, logos and Lottie animations

An SVG is the best thing to bring in, because its text stays text. Other files work too. This section says where each one goes, what NoaCG does to it, what comes out in an export, and what happens when a font is missing.

FileWhat it is good for
PNG, WebPA finished design, or a logo. Both carry transparency, which is what lets video show through.
JPEG, AVIF, GIFPhotographs and stills. No transparency in a JPEG, so it covers whatever is behind it.
Lottie (.json)A vector animation out of After Effects. Stays sharp at any size and weighs almost nothing.
A font file (.woff2, .woff, .ttf, .otf)A licensed face your design needs. Taken by the SVG import when it lists the families it found.
Video (.webm, .mp4)A short sting inside a graphic. Capped at 3 MB, so it is not the way to play a clip.

Three ways in

  • As the graphic itself. The studio → New graphic → Import graphic takes a PNG, a JPEG or a WebP as readily as an SVG. You clean the artwork up, place the text fields yourself and pick how it moves. Nothing is redrawn. A picture has no layers to read, so you place the fields yourself instead of the file naming them.
  • As a logo on a catalog design. Designs that carry a mark offer a logo slot while you make the graphic, and you upload your file into it. The slot is a real image field, so you can also leave it empty now and fill it at playout.
  • As a file in the graphic. Not open right now. Extra files, a Lottie animation among them, were added in the old code editor, and that editor is closed. The new editor lists the files a graphic carries but cannot add one yet, so a graphic keeps the files it arrived with.

Pictures for a live show are separate. On a production, Add pictures builds one picture graphic that holds all of them, with a cue each. Taking picture three replaces picture one instead of stacking on top of it. A production takes up to twenty.

Nothing is linked. Everything is carried

A file you bring in is copied into the graphic, and the graphic keeps the bytes. There is no link back to your computer, no folder that has to stay where it was, and nothing is fetched over the network when the graphic plays. That is what lets a package work on a playout machine with no internet.

So an address on the web is not a substitute for the file. The studio warns about one, and a machine that never reaches it shows nothing at all.

An imported picture larger than the frame it is drawn in is re-encoded at the frame's own size. Nothing on a 1920 × 1080 canvas can use more pixels than that, so this costs no quality.

  • A PNG stays a PNG and a JPEG stays a JPEG. An SVG is never touched.
  • The result is kept only if it actually came out smaller.
  • Artwork smaller than the canvas stays at its own pixel size. It is never enlarged and softened.

Transparency is the one thing to get right before you import. A full-frame picture with no transparent areas covers the whole picture on air. That is right for a title card and wrong for a lower third. The fix is in the program you drew it in: export again as a PNG or a WebP with a transparent background.

What comes out in an export

Packages come in two shapes, and your files are handled differently in each:

  • A folder package (OGraf, or a playout system that loads a whole template folder) writes them out as real files beside the template: your pictures under images/, fonts under fonts/, and the animation engine in a folder of its own. Paths are relative, so the folder can be copied anywhere.
  • A single-file package (CasparCG, an OBS or vMix overlay) has nothing to sit beside, so every one of those files is embedded in the one HTML file instead.

Either way the package is complete and works from a local disk.

The operator page in the package lets an image field switch between the pictures that graphic already carries, plus None. It is not a file browser. If an operator will need another logo on the night, bring it in before you export. Setting the field back to None returns the design's own placeholder.

Lottie animations

A graphic that already carries a Lottie keeps it. Adding one is not open right now (see the ways in).

A Lottie plays as soon as the graphic loads and it loops. It is not driven by the graphic coming on and off air, so it suits a badge, a spinner or a looping ornament rather than something that has to hit a cue.

The player is about 165 kB, and only graphics that use a Lottie carry it. It is bundled, never fetched. The animation travels inside the package too, as a file beside the template or embedded in it, and nothing about it reaches the network.

Fonts, and what a missing one does

A missing font is silent. It is not an error and it does not stop anything. The browser falls back to the next family it has, so the graphic comes up in the wrong typeface at a slightly different width. It looks close enough that nobody notices until it is on air.

That is why NoaCG packages fonts instead of naming them. A typeface you picked in the studio is written into the package, and its licence travels with it. A face of your own comes in through the SVG import's font matching, which lists the families your file names and takes a file for each one. It is packaged the same way.

When a font file is missing, the two package shapes behave differently:

  • A folder package still builds, and you can repair it by dropping the file into fonts/.
  • A single-file package refuses to build. There is no folder to repair, and the alternative is a graphic that quietly airs in the wrong face.

Which package do I want

Every graphic exports to all six packages below, and you do not pick one while you design. You pick at the end, by what will put the graphic in the picture. Find that system in the table, take its row, and read the guide it points to if there is one.

First: are you exporting at all? If NoaCG is running the show, the answer is no. A production gives you an output URL to add as a browser source and an operator page to drive it from, and nothing is downloaded.

Export when you hand the graphic to a system that will own it, or when it has to run on a machine that will not have this page open.

OBS, vMix & any browser source

A published production has one output URL. It shows the whole show on a transparent background, and the playout dashboard drives it live. Any source that can load a web page can show it.

  • Copy the URL from the Output links button in the production page header. It ends …/output?production=<slug>, where the slug is a random id made when you publish. You never type it.
  • Load it once and leave it up. The operator cues the graphics, so there is no need to reload the source.

Four rules apply to every browser-based playout:

  • The page is already transparent. Do not add a chroma key. If you see a black or white box behind the graphic, the host is forcing a background: check its custom CSS and background settings.
  • Match the resolution exactly. Graphics are made in real pixels, 1920×1080 unless you chose otherwise. A different size scales the picture instead of cropping it, and scaled text looks soft.
  • Resize the source, never the layer it sits on. In OBS, set the browser source's own Width and Height. Dragging its box in the scene scales the finished picture, and the text goes soft again.
  • Set the source's FPS to the channel's. Motion plays at the right speed at any rate, but a 30 fps source in a 50 Hz channel judders. That is easy to mistake for a fault in the graphic.

OBS Studio

  1. Sources → + → Browser.
  2. Paste the production's output URL. For an exported overlay, unzip the export first, then tick Local file and pick <name>.html from inside the unzipped folder.
  3. Set Width and Height to the graphic's own resolution, and FPS to your channel's.
  4. Leave the background alone.

Leave "Shutdown source when not visible" off for a production output. When it is on, OBS tears the page down each time you hide the scene and rebuilds it when the scene comes back.

An exported overlay comes with a small launcher: Start controller.cmd on Windows, start-controller.command on macOS and ./start-controller.sh on Linux. It serves the folder locally, opens the operator page and relays every command into the graphic that OBS or vMix is showing. It needs no network and nothing to install.

vMix

  1. Add Input → More → Web Browser.
  2. URL: the output URL, or the full local path to an exported file.
  3. Set the width and height to the graphic's resolution.
  4. Use it as an overlay channel input.

CasparCG

CasparCG plays web pages through its HTML producer, so there are two ways in: load the production's live output URL, or play an exported file from disk with no network at all.

Playing the production's output URL

CG 1-20 ADD 1 "https://noacg.studio/output?production=<slug>" 1
  • 1-20 is channel 1, layer 20. Use whatever your rundown expects.
  • Put your own production's URL in place of the quoted one. It is behind the Output links button on the production page.
  • The URL is a capability: anyone who has it can show the production, but not operate it. Treat it like a password.
  • Load it once at the start and leave it up. Graphics are cued from the dashboard, not by adding the layer again.
  • While you set up, add &debug=1 to see a status readout on screen. Take it off before air.
  • After a network drop or a layer restart the page recovers by itself. It rebuilds what was on air without replaying the animations.

Letting NoaCG load the layer for you: NoaCG Bridge

Instead of typing the command into the CasparCG Client, you can let the production page send it. A browser cannot open the raw TCP connection that AMCP uses, so a small program on the machine you operate from does it for the browser: NoaCG Bridge.

  1. Download NoaCG Bridge from the Downloads page. It is the newest Bridge release on GitHub, and Playout on a production page links it too.
  2. Double-click it. There is nothing to install: the file is the whole program. Windows warns once because it is not signed yet, so choose More info, then Run anyway. Leave its window open while you work.
  3. It opens a page in your browser. One click pairs the browser with the Bridge.
  4. The same page then connects to your CasparCG server: enter its address and AMCP port once and press Connect. It sends a real AMCP VERSION and shows the version string the server answers with. NoaCG Bridge remembers the servers you connect to, so the next time you pair it connects to the last one by itself, and the others are one click away.
  5. Name the server's channels and the layer graphics go on under Playout in a production's header (the same form is under Settings → Playout). Test connection there checks the server without changing what is remembered.

The production page now has a Put on air / Take off row beside its output URL, and Put on air sits beside Connect in its Playout settings too. Put on air sends the one command above, and only when you press it: pairing and connecting never touch a layer. From then on every cue, reveal and score change travels over the production's own command log into the page CasparCG is showing, and the Bridge sends nothing more.

Network and browsers

  • The Bridge listens on 127.0.0.1 only. CasparCG can be any machine on the studio network, as with the Client, and nothing is exposed to the internet.
  • On the hosted studio, the browser asks once whether the site may reach your local network. Firefox words it “access other apps and services on this device”. The pairing page tells you before you click.
  • Chrome and Edge are recommended, and Firefox works. Safari refuses to let a page reach a local program at all, and has no setting that allows it.
  • A browser set to forget site permissions, which is common on shared school computers, asks again every day or every tab. The browser notes on the Downloads page name the policy that allows NoaCG once, for good.

Templates and clips already on the server

With the Bridge paired, the foot of the rundown has ＋ From the playout server…. It lists the HTML templates and media in the server's own folders, folder by folder, as the server lists them. Hover a name to see its full path. Pick one to add it as a cue beside the production's graphics.

  • A server template is taken with its field values, updated, stepped with Next and taken off.
  • A clip rolls, pauses, resumes and stops. Tick Loop in a clip's cue and CasparCG repeats it until you take it off.
  • Clips play on layer 10, below every graphic, so a lower third never disappears behind a rolling clip.
  • The file stays on the server. The production stores only its name.

The list comes from the server's media scanner, which runs beside CasparCG: scanner.exe in the Windows download, a separate scanner process on Linux. When it is not running, the picker says so and still lets you type a template or clip name.

A template NoaCG exported brings its fields with it. For any other template, type its field ids (f0, f1) once. Get them from its own FIELDS.md or from its author.

Channels and layers

A CasparCG channel is whatever your studio makes it: a key channel into a vision mixer, a fill channel, a screen in the set. NoaCG does not decide. List the channels your server has under Settings → Playout, then put each server item where it belongs:

  • Add channel adds Channel 2. A name is optional.
  • Every server video, still, audio file and template has a Channel pick beside its Layer in its editor. The rundown shows its address the way CasparCG writes it: 2-10 is channel 2, layer 10.
  • NoaCG output is where NoaCG plays the production's own graphics, 1-20 unless you change it. Media on that channel plays under the graphics on a lower layer (videos and stills start on 10, audio on 5) and over them on a higher one. No server item may use the output's own layer: playing something there would replace the output.
  • New media is the channel a newly added video, still or audio file gets.
  • All out takes off every server cue the rundown put up, on any channel, and leaves everything else on the server alone.

A studio with one channel sees one row, and nothing changes.

Video with transparency

A video with an alpha channel can play over the programme from a key channel, for example as fill and key into a vision mixer's downstream keyer. Render it as ProRes 4444 or QuickTime Animation with premultiplied alpha (in After Effects, "Premultiplied (Matted)" with black). CasparCG reads a video's alpha as premultiplied, so a straight-alpha render looks too bright wherever it is partly transparent: soft edges, shadows and fades. WebM (VP9) alpha does not work on CasparCG 2.3. Transparent PNG stills are always right. On the vision mixer, set the keyer to a pre-multiplied key.

Checked on CasparCG 2.3 and 2.5 by recording the channel. Not yet checked through an SDI card and a vision mixer.

Playing an exported file

Export with the CasparCG target and you get one self-contained .html, with fonts and images inside it and no network needed. Put it in the server's template folder, which is the template-path in casparcg.config, and drive it as a normal HTML template.

The playout dashboard

A production is one show: its graphics, a rundown of cues you prepare in advance, and one output URL that stays the same. Each graphic is its own layer, so a bug, a lower third and a ticker can be on air at once.

Making one

  1. In your library, press + Production on a graphic's row. Pick a production you already have, or type a name in the New production… field to make one with that graphic in it.
  2. Add the show's other graphics the same way. A graphic you are still making goes in from the wizard's Finish step, in one press.
  3. Build the rundown on the production page. A cue is a graphic plus the values it airs with.
  4. Press ▶ Start production in the page header. This publishes the show and makes two links: the output URL that a browser source loads, and a control page for operating from another device.

Both links are behind the Output links button in the header, each with a Copy button. Publishing needs an account, because the published pages live in your cloud space. Everything before it works offline.

The header reads NOT PUBLISHED before you publish and SHOW after. To send later changes to the output, press ⟳ Publish changes in the Output links panel.

Running it

  • Preview, then take. The page has two panes. Preview is what you are checking, program is what the audience sees. Select a cue, check it in preview, then press Take. Selecting and previewing never reach air, and an edit airs only on a take, never while you type.
  • Any browser can drive it, including an OBS dock or a phone at the desk.
  • It recovers by itself. Every command is saved in order. After a network drop or a restart, the output catches up in that order and rebuilds what was on air without replaying the animations.
  • Pictures need no template. ＋ Add pictures… turns image files into cues, such as a holding slide or a sponsor card. There is one picture layer per production, so a new still replaces the last one.

Working with other people

Two different things both get called sharing, and they have different answers:

  • Running one show from several devices needs no accounts at all.
  • Preparing one show together, each person signed in as themselves, is what a team is for.

Running a show together needs no accounts

Publish the production and it makes links that work for whoever holds them. All of them are behind the Output links button in the production page header, each with a Copy button.

  • The control page drives the show from a second laptop or a phone at the desk.
  • The presenter view shows the host what is coming, without the operator controls.
  • The output URL is what a browser source loads.
  • The audience join page collects votes and messages.

Three people can run one show this way today, with one account between them and nothing to set up. The playout dashboard and audience join pages cover what each link does.

Links do not settle who may edit the rundown, who may republish a changed graphic, or whose account the show goes away with. That is still the one account that made it. A team is how that changes.

Make a team

Sign in first. Teams are an account feature. An offline build has no team features at all, and a signed-out visitor sees no mention of a team unless somebody sends them a join link. That link asks them to sign in or make an account.

  1. Open a production you own and press Share in its header. The same dialog is Share with a team… in the ⋯ (More actions) menu on a production's card in Productions. There is no team entry in the topbar or in Settings: a production is the only door.
  2. Press ＋ New team…. It is the quiet text button under the list, not the amber one in the footer.
  3. Fill in both boxes. Team name is what the class or the crew is called. Your name, as teammates see it is you. It starts as the part of your email before the @, and you can change it.
  4. Press Create team. The next screen shows the join code and the member list, with you on it as the owner.

Teammates see your name and nothing else. Email addresses are never shown to anybody.

Get somebody in

The team screen shows a large join code. Under it is a link ending #/join-team/<code>, with a Copy link button.

Send the link, not the code. The screen that takes a code opens only from a join link, and nothing else in the app leads to it. So a code read out to a room gets nobody in who does not already hold a link. Paste the link into the class chat, or wherever you already talk. There is no email invitation.

A code is still a key. Anybody who has ever held a join link to any team, including last term's, is one paste away from using a code they overheard. Treat a code like the link it belongs to.

The person who gets the link opens it in their own browser, signs in or makes an account, types the name teammates will see and presses Join team. Nothing else is asked. Joining shares nothing from their library, and nothing from yours.

Anyone in the team can pass the link on. Only the owner can press Rotate code, which makes a new code and retires the old one for joining. Everybody already in the team stays in, so rotate when a link reaches the wrong chat.

Your display name is fixed when you join. The only way to change it is to join again through the team's current link with a different name. A rotation retires the link you were sent, so get the new one from somebody in the team first.

Who can do what

There are two roles. Whoever made the team is its owner, and everyone else is a member.

Every Yes below has one condition: you need a production of your own to open the team dialog. A member who joined a class team and has made nothing yet cannot see the join code, the member list or the way out. Make a production of your own, even an empty one, and the door is there.

What has been verified

Run against the live backend: making a team, handing out its link, joining through it, reading the member list, rotating the code and deleting the team.

Removing a member and leaving a team are built, and the database refuses them correctly. They have not yet been run with a second person in the team, so treat them as expected rather than proven.

Moving a production into a team does not work yet. The Move to team button in that dialog is switched off on purpose, because the list a moved production would appear in has not shipped. So a team you make today is the group, ready for the production that will go into it. To work on a show together in the meantime, use the links above.

What will happen when a production moves in

None of this can be tried yet. It is here so that you know what moving a production will commit you to before the button turns on.

  • A production has one home. Moving it into a team takes it out of your personal list and gives it to the team. Only the team owner can move it back or delete it.
  • Every member can edit its rundown, republish its graphics and operate it. If two people save at once, the second save is refused and says who got there first. Nobody's work is quietly overwritten.
  • Graphics travel as copies, as they already do when a graphic joins a production. Nobody's library is opened to anybody, and the original stays personal.
  • The links do not move. Whoever republishes it, the output URL and the control page URL stay the ones you already gave to OBS or CasparCG.
  • Preparing it will need to be online. A team production lives on the server rather than in the copy your browser keeps, so there is no offline edit. A personal production is unchanged and still works offline.

Whose storage it counts against

Nothing is enforced yet. Storage and project counts are recorded but not limited, on personal and team space alike.

The rule for when limits arrive is already decided: a team production's bytes count against the team owner, the one account that can also delete it. Graphics stay where they have always been, in the library of whoever saved them.

Audience join pages

A production can invite its audience in. A public join page at a readable URL, noacg.studio/join/<name>, collects viewer messages and votes from any phone, with no app and no account. It is the kind of address you read out on air.

The link is behind the same Output links button as the output URL. Its name comes from the production's name at the first publish, and the Readable name row changes it to something you can say out loud. Do that before you give the link out: a new name breaks the old one, and everybody already typing it is left at a dead address.

  • Nothing viewer-written airs on its own. Send-ins land in a moderation inbox, and an operator picks what goes into the graphic. There is no setting that airs a send-in automatically.
  • Votes tally live into poll graphics. Open the vote from the audience workspace. The board's own buttons close it, show the result and call the winner when you are ready. The board can be one of ours or one you drew yourself.
  • A presenter view (a separate link) shows the host what is coming without giving them operator controls.

You do not need a Twitch or YouTube channel for any of this. An audience with no Twitch and no YouTube walks the whole road on one small show, from publishing to a vote on air.

Graphics with behaviour

A lower third plays and stops. A quiz board has to know which answer the contestant locked in, and whether it has been revealed yet. NoaCG graphics can carry that logic themselves, as named states and operator events.

The control panel is built from those states, so a move the current state does not allow is greyed out.

  • A quiz runs Select answer, Lock it in, Reveal. Each one is a button on the dashboard, and each is legal only when the board's state allows it.
  • A scoreboard carries score up/down and clock start/stop as events. The numbers are data an operator or a feed writes.
  • A live vote opens, closes and shows a result. The bars are driven by a real audience at your join link.
  • Data never causes a state change. Updating a name or a score redraws those fields and nothing more. A graphic changes state on an operator's press, or on its own timer where the design has one, and never because a value arrived. So a feed can be left running through the whole show.
  • Everything still degrades to plain stepping. Hand the same graphic to any playout system and it walks its steps in order like an ordinary template. The extra buttons appear when NoaCG drives it.

You can build behaviour without writing code. An imported SVG board is made of layers. Draw each moment you need, hide those layers in the design app, and the import wires them up: for a quiz, answer picked, right, wrong and locked in.

See the SVG guide, and how to draw a live vote for the layer names a vote board wants.

Live data

There are three ways to get data in, from no setup to fully automated. One rule holds for all three: a data update changes what a graphic shows, and nothing else. It cannot play a graphic, take it off, or move it to another state.

Data updates and operator commands go into the same log, and they apply in the order they arrive. So an operator's change made after a feed update wins.

Type it on the dashboard

Every field is editable live from the production page: edit, stage, take. For most shows nothing else is needed.

A Google Sheet (or any published CSV)

A graphic pointed at a published sheet follows the sheet, so anyone with edit access to the sheet can change its fields. In the sheet: File → Share → Publish to web → CSV.

Connecting that link to a graphic was done in the old code editor, which is closed, so a new link cannot be connected in the studio right now. A graphic that already follows a sheet keeps following it. The polling code is ordinary, commented JavaScript inside the graphic, with column headers mapped to field titles, and it runs wherever the graphic runs.

To bring a sheet into a show today, import it as a table on the production's Data tab, or push the values with the Production Data API below.

The Production Data API

For a timing system, a results service or your own scripts: push values into a published production over plain HTTPS, authenticated by the production's own data key. Writes become rows in the production's command log, so the renderer cannot tell your update from an operator's.

Where to find the key. Publish the production, open its Data tab, and press ▾ Data key in the Production data panel. Reveal it, copy it, and put it in your integration's server-side configuration. Publishing again mints a new key and the old one stops working, which is also how you revoke one. 

curl -s https://noacg.studio/api/data/update \
  -H "Authorization: Bearer $NOACG_DATA_KEY" \
  -H "Content-Type: application/json" \
  -d '{"graphic": "House Scorebug", "values": {"Score A": 2, "Clock": "43:12"}}'
  • Fields are addressed by the labels the graphic shows its operator ("Score A").
  • The key writes data and reads the production's current data back. It cannot play, stop, take or clear anything. Cueing and clearing stay with the operator.
  • /api/data/patch (PATCH, or POST behind a proxy that eats PATCH) writes to a data path such as match.home.score instead of to a named graphic. Every graphic whose field is bound to that path follows, so the feed does not have to know the rundown. The binding is set up in the studio first.
  • A worked example ships in the repository: a weather mini-pack driven by a small Node connector polling Open-Meteo. The full reference, limits and error shapes are in DATA_API.md.

None of the three says what any of it is for. One show, worked through is the same machinery with a real rundown around it.

One show, worked through

Hall Cup is a school sports night. It has four graphics, one data tree, one table and a hall full of phones. Every picture below was taken while building it.

The tree: what the whole show knows

Open the production and go to its Data tab. Press ▾ Raw JSON, paste this in, and press Apply JSON. 

{
  "match": { "teamA": "Otava", "scoreA": 2, "teamB": "Karhut", "scoreB": 1 },
  "tickerItems": [
    "Junior final starts at 19:30",
    "Canteen closes at 20:00",
    "The bus home leaves from gate 4"
  ]
}

That address is a path. Dots walk down the tree. The number 2 lives at match.scoreA, and the three ticker lines live together at tickerItems.

You do not have to paste JSON. The row at the bottom adds a path and a value by hand. If the path does not exist yet, it is created.

  • The type is kept. 4 is a number, true is a boolean, [1, 2] is a list, and anything else is text. Number rows get − and + buttons. A list is one line per item, which is what a ticker's text box takes.
  • This is state, not a command. Nothing on this panel plays, stops or takes a graphic. That is the rule of Live data. It is why a feed can run all night without putting anything on air.
  • Save the numbers you want to start from. ⬇ Save as seed stores the current tree in the production itself. ⟲ Reset to seed puts it back. Do it before the first rehearsal: until the production is published, the live tree exists only in this browser.

The bindings: which field reads which path

A path does nothing on its own. A binding points one field of one graphic at one path. Scroll to Bindings and press Bind all by title.

It matched by the words. "Score A" found match.scoreA: the last part of that path is the field's title, once case, spaces and punctuation are ignored. "Ticker items" found tickerItems the same way.

Nothing was guessed. If two paths match one title, the row stays empty and names both. A binding that is right half the time is worse than a box you fill in once.

The strap's Name and Title matched nothing. That is the correct answer, not a gap: a guest's name is not something the whole show shares.

To bind a row by hand, click its box and pick a path from the list, or type one. To unbind it, press ✕ twice.

One value, every graphic

Press + beside match.scoreA on the Data tab. Both scoreboards now say 3, whichever of them is on air and whichever was cued first.

That is what binding is for. The score belongs to the show, not to one cue. Nobody has to remember to retype it on the half-time card.

You can also change it from the Playout tab. A bound field shows there read-only, with its path beside it. The ± LIVE NUMBERS row underneath changes the shared value with one press.

Where the tree lives depends on one thing, publishing:

  • An unpublished production keeps it in the browser you are using. That is why the seed is worth saving.
  • A published production keeps it with the production. Every operator and every feed sees the same numbers, and the Data API writes into this same tree.

The table: rows an operator picks from

Hall Cup interviews three people. Their names belong to no particular moment in the show. That is what a table is for: a bank of rows, none of them live. The operator loads the row they want, when they want it.

Under Tables, choose Line-up / roster and press ＋ New table. Call it Interviews. It starts with the columns Name, Number and Position. Rename Position to Title, remove Number, and type the rows.

The matching is by words again:

  • A column called Title loads into the field called Title.
  • A column that matches no field is carried along and ignored.
  • A field that no column names keeps whatever it had.

So a spreadsheet that already uses your field names needs no mapping step. ⬆ Import CSV / JSON takes it as it is, and then says which of its columns matched. ⬇ Blank CSV goes the other way: it gives you a file with the right header row to fill in.

Now go back to the Playout tab and select the House Strap cue. It now has a Load data row control. Picking a guest fills the cue you are editing, which is the preview, and nothing more. The name goes on air when you press ⟳ Take, like everything else.

A score belongs in the tree. Two graphics show it, and it changes while one of them is on air. A guest's name belongs in a table. Only one graphic ever shows it, and the operator decides which guest.

When both would work, ask one question: does more than one graphic need the same value at the same time? If it does, use the tree.

An audience with no Twitch and no YouTube

The first panel on the Audience tab is Chat sources. It asks for a Twitch channel or a YouTube video. Most people running a hall, a school event or a club night have neither, and they are not missing anything.

Those two only pull an existing chat into the same inbox. The room's own join page takes messages without them, and that is what Hall Cup uses.

First add two more graphics from the catalog: House Question (Audience & questions) for the messages, and House Vote (Live votes) for the poll. Then:

  1. Publish the production. Nothing for the audience exists until you do. An unpublished production shows ▶ Start production in the header and has no links to give out. Publishing is free and needs an account.
  2. Get the audience link. Press Output links in the header, then Audience link. It reads noacg.studio/join/<name>. The name comes from the production's name when you first published it.
  3. Give it a name you can say. The Readable name row below the link changes it to something you can read out loud. Do this before you hand the link out, because a new name stops the old link working.
  4. Give it to the room. Read it out, put it on a holding slide, or print a QR code of it. There is no app to install and nothing to sign in to.
  5. Open the door. On the Audience tab, tick Accepting messages. Until you do, every phone with the link says the production is not taking part right now.

Hall Cup leaves the mode beside that tick box on Questions. Comments works the same way and asks for something shorter. In both, the heading on the viewer's page reads "Send us your question", and nothing changes that yet.

Nothing a viewer sends can go on air by itself. Every message lands in the inbox on the same tab. From there it takes two steps to reach air:

  1. The operator presses → Send to rundown. That adds an ordinary cue to the House Question graphic.
  2. The operator takes that cue, like any other.

No setting skips those two steps. Before sending, the operator can edit a broadcast version of the message. What the viewer actually sent is never changed.

Rehearse before the room exists. On an unpublished production the bar has ⟳ Simulate 3 arrivals. It makes up messages so you can practise the whole moderation round with nobody watching.

Each made-up message says "(rehearsal)" in its text, so nobody can mistake it for a real one. A published production has no such button, because a real audience is sending there.

Putting a vote to the room

Type a question under Put a question to the room. Give it two to eight options, one per line, and press Open voting. Every phone with the link switches to the ballot at once. A viewer can change their vote while voting is open.

Stage counts to a graphic writes the question, the options and the counts into a cue for House Vote. Take puts it on air. Press the button again while voting is still open and the same cue is updated, not copied, so the rundown does not fill up with one row per refresh.

The figures on air change when the operator shows the result, not while the room is still voting. That keeps a reveal a reveal.

A board you drew yourself can have a Live figures layer. The Audience tab then offers a tick box to show the percentages live instead. A catalog board like House Vote has no such layer, so this show does not get the tick box.

What was and was not run

Everything in this section was run in the studio: the tree, the bindings, the table and loading a row, the inbox, and a vote from opening it to staging the counts.

One step is taken on trust: the published noacg.studio/join/<name> link itself, which needs an account and the hosted backend. The page a phone loads there is the one in the picture above, drawn by the same code.

Make graphics with Claude Code, Codex or any coding agent

  1. Use Claude Code, Codex or another compatible coding agent.
  2. Install the NoaCG CLI for your agent. One prompt does the setup, or run the commands under Reference.
  3. Prompt the graphic you want. In Claude Code you can also type /noacg:graphic.
  4. It appears in your NoaCG library, ready for a rundown.

A coding agent can already write HTML, CSS and JavaScript. On its own, that code has no operator controls, no buttons an operator can press, and no promise about how it behaves in a playout system. The NoaCG CLI adds what is missing:

  • It gives the agent the contract a NoaCG graphic has to meet.
  • It checks what the agent wrote with the studio's own validator.
  • It saves the graphic into your library once it passes.

The result is an ordinary NoaCG graphic. You put it in a production, operate it with the buttons its behaviour defines, and feed it live data from a sheet or an API.

Paste this to your agent and start building

One prompt does the setup. Your agent picks the install it needs, runs it, checks that it worked and asks you what to make. It runs a couple of install commands that you have to approve. 

Set up NoaCG Studio so you can build broadcast graphics for me, then ask me what to make.

1. Install whichever of these matches you. Claude Code:
     claude plugin marketplace add NoaCG/NoaCG-Studio
     claude plugin install noacg@noacg-studio
   Codex:
     codex plugin marketplace add NoaCG/NoaCG-Studio
     codex plugin add noacg@noacg-studio
   Any other agent that speaks MCP: register a stdio server, command "npx", arguments
   "-y @noacg/cli mcp". I will approve these commands as you run them.

2. Do not wait for the install. A plugin only loads in your next session, so use
   "npx -y @noacg/cli <command>" for everything today, starting with
   "npx -y @noacg/cli docs contract" to read what a NoaCG graphic must expose.

3. Verify: "npx -y @noacg/cli doctor" prints the deployment, the browser it will drive and
   the bridge version it found. If it does not, tell me what failed and stop.

4. Then tell me in one or two lines that NoaCG is ready, and ask me to describe the graphic
   I want.

The loop after that: scaffold or author, "npx -y @noacg/cli validate <dir> --screenshots
./shots", fix what it reports, then "npx -y @noacg/cli save <dir>". Saving needs
"npx -y @noacg/cli login" once, which opens a browser for me to approve.

You need:

  • Node.js 20 or newer.
  • Chrome or Edge installed on the system. The validator runs it in the background, with no window.
  • An account, but only when you save a graphic into a library.

To run the install commands by hand instead, see Reference.

Then describe the graphic you want

For example: "Make me a clean scoreboard for a floorball stream: home, away, period, clock." In Claude Code, /noacg:graphic starts the same thing.

The noacg-graphic skill tells the agent how a NoaCG graphic is built, which tools to use, how to validate it and how to save it. It says nothing about how the graphic should look. That stays the agent's job.

The plugin brings the skill from your next session on. Until then, noacg docs prints the same texts.

The agent then works in five steps:

  1. Scaffold. It creates a starting package with the fields and operator events of a graphic type. This step is optional. It can also write from scratch against the contract.
  2. Author. It writes the graphic, the way it writes any code.
  3. Validate. The studio's own checks run, then a live playout test. The agent gets screenshots off air, on air and with doubled text, so it can see what it made.
  4. Fix. It works through the findings until there are none. They read like compiler errors.
  5. Save. The graphic goes into your NoaCG library, and the agent prints its link.

Saving is the one step that needs you. Log in once per machine, and approve it in the browser that opens: 

npx @noacg/cli login

The key it stores can only save graphics to your library and send packages to your Home. To revoke it, go to Settings, then Account, then Agent access.

save refuses a graphic that does not pass validation. A saved graphic is editable in the studio like any other, and exports to every target NoaCG supports.

Ask for a whole package

For example: "Make me the graphics for a fight night: opener, name straps, fight bug, round card."

The agent builds each graphic, then sends them together with noacg pack --save. The package appears on your Home under Waiting to install. Press Install. The production opens with its layers and running order, ready to operate.

Reference

The install commands, one by one. These are the commands the prompt above runs. All three routes install the same package.

Claude Code. The plugin brings the noacg-graphic skill and the /noacg:graphic command. Nothing needs installing first. It runs nothing until you make a graphic, because the skill drives the CLI from the terminal. A session about something else pays nothing for it. 

claude plugin marketplace add NoaCG/NoaCG-Studio
claude plugin install noacg@noacg-studio

An optional second plugin adds an MCP server that is always on. It puts the noacg tool in every session and keeps a browser warm between calls. It costs a process and some context in every session, which is why it is separate. 

claude plugin install noacg-mcp@noacg-studio

Codex. The same plugin, from the same repository.

codex plugin marketplace add NoaCG/NoaCG-Studio
codex plugin add noacg@noacg-studio

Any other agent that speaks MCP. Register the server over stdio, with the command npx and the arguments -y @noacg/cli mcp. It brings the tools, and the contract text comes with them as the server's resources. 

npx -y @noacg/cli mcp

A plugin loads when a session starts, so the session you installed it from does not have it yet. That is why the prompt above uses npx for the first graphic.

The package. All three routes install one npm package, @noacg/cli. It gives you one command, noacg. You can also install it yourself: 

npm i -g @noacg/cli

Or run any command with nothing installed, as npx @noacg/cli <command>. The loop by hand is three commands: 

npx @noacg/cli scaffold --type scoreboard --design neutral --out my-scorebug
npx @noacg/cli validate my-scorebug --screenshots shots
npx @noacg/cli save my-scorebug

scaffold creates the --out folder relative to where you run it. The folder has to be new or empty. noacg types lists the graphic types the deployment knows, with their fields and operator events. That is where a --type value comes from.

The MCP server without the skill. This gives Claude Code the tools without the plugin, for the folder you run it in: 

claude mcp add noacg -- npx -y @noacg/cli mcp

To have it in every folder, add --scope user before the name:

claude mcp add --scope user noacg -- npx -y @noacg/cli mcp

A server added this way runs in every session of that scope. The noacg plugin runs no server at all: its skill drives the CLI from the terminal.

The server has one tool, noacg. Its command is the CLI verb: types, scaffold, validate, inspect, screenshot, docs or save. So an agent can read the contract through docs before it has a deployment or a key.

Which files to edit. A package holds sources and generated files. Edit the sources: <name>.html, css/template.css, js/template.js, and the images/ and fonts/ folders.

Leave the generated files alone: <name>.ograf.json, graphic.mjs, FIELDS.md, README.md, GETTING-ON-AIR.md and controlpanel.html. validate rewrites them from the sources, so an edit made there is lost.

Which deployment it talks to. https://noacg.studio, unless you set one of these environment variables:

  • NOACG_URL points it at a local dev server or a self-hosted one.
  • NOACG_BROWSER names a Chromium executable, when the system Chrome or Edge is not the one to use.
  • NOACG_AGENT_KEY supplies a key in CI, where nothing can open a consent page in a browser.

When something fails and the findings do not say why, run doctor. It prints which browser it will drive, which deployment NOACG_URL points at, the bridge version it found there, and whether a key is held. 

npx @noacg/cli doctor

What the package is. The folder is at the same time a valid SPX package and an EBU OGraf v1 graphic, with no build step. Zip it and it imports through the studio's Import door, or plays in any OGraf renderer.

The graphic itself is plain HTML, CSS and JavaScript. So the same sources also export to CasparCG, an OBS or vMix overlay, H2R and LiveOS. The full reference is AGENT_CLI.md.
