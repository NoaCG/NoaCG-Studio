## Exact missing rule and chosen policy

The new Blank graphic action can accept a durable creation while its initiating wizard still offers departures. Retained startBlankGraphic9–10 later unconditionally closes/navigates. Suppressing only that callback is insufficient: `authoringProjects.restore:140–150` itself restores the created document and sets galleryOpen:false; `App:240–247` can consequently rewind a still-new route to Home. It is false to promise an enabled “Cancel (keep current project)” after the creation has already been accepted.

Choose the ordinary bounded busy-operation convention, local to the NEW wizard Blank action. Once this creation is accepted, its initiating wizard temporarily declines cancellation, walk changes and same-document navigation until its existing durable operation settles. Do not accept Home/another walk and later override it; those actions are visibly busy-disabled during this interval. Do not queue/replay a declined departure after completion. Other Studio state/services are not locked and no shared persistence/router API changes are proposed.

This deliberately differs from allowing an accepted departure while the same creation later restores/closes the wizard. That alternative cannot be guaranteed by the retained helper alone and is NOT claimed here. The existing ProjectStarter ×/late-navigation analogue is pre-existing/nonblocking under the saved review; it is not silently repaired or reclassified as E4. Existing starter creation still uses its current guard/persist path, while the new Blank graphic gets the local lifecycle rule below.
