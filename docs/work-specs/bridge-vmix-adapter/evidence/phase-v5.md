# V5 evidence for the vMix clip clock and reload

Previous verified main is `1b7e067c537d567e119c5f886b22f521b2a80503` (#2378). V5 covers AC-11 and the V5 Windows Bridge release in AC-6. Trim, fades, levels, clip sequences and operator-device verification belong to later phases.

## Rules

- A paired production using vMix and a Bridge advertising vMix media reads one vMix player snapshot at a time. It applies the snapshot only to the players its current cues or live state use. It keeps the existing hot and idle cadence, wakes after a player action or when the page becomes visible, and performs reads without sending any mixer, overlay or output command. CasparCG keeps its channel readings.
- A read belongs to the same live production, playout system, pairing and media-folder revision from request to fold. A production switch, unmount, delivered pairing change or folder publication retires pending reads. This also covers an uncertain folder choice and a switch away and back with the original credentials. Before applying an answer or sending or recording a cue action, check the current stored production and cue-to-item binding. A deleted, reassigned or mismatched cue cannot regain authority.
- vMix Take writes the production, cue and item identity into the existing opaque cue field the Bridge echoes. Copies can retain a cue ID, and two cues can name the same file. Recovery requires a Bridge instance from the reported session, the exact production and cue, a current vMix media item on that player, and the item's exact selected relative path including its extension. The Bridge preserves the original chosen name. For an in-root alias it can echo that name only when it still resolves to the held canonical file under the current media folder. A retargeted alias or a different media root cannot attest to the old cue. The scoped cue field fits the Bridge's 200-character envelope without truncation. An imported identity outside that envelope cannot recover by a shortened ID. A legacy unscoped Take cannot be adopted on reload or by another production. The old page that accepted it can keep its in-memory ownership under the existing rules. CasparCG cue IDs keep their current format.
- The paired player reply must have valid HTTP and protocol fields, one well-formed row for each player, a Bridge session and observation time, and internally consistent generation, playback and identity fields. Missing, duplicate, malformed or contradictory evidence makes no change. The Bridge reports an ambiguous or unreadable player snapshot as unavailable before it changes any saved player instance. A confirmed foreign selection, including a file outside the media folder, can be reported as occupied without identity. The existing conservative continuity check detects a nonlooping position jump back of more than 750 ms. vMix does not expose a unique occurrence for arbitrary native edits between snapshots. A valid still or completed clip retains observable identity without implying a moving or usable countdown. For the same session, ignore a player generation below the last accepted action or previous admitted observation, and ignore backwards observations. Both players share one Bridge process session. An admitted new session starts its counters over and retires the old session on both players, even when one player's action is pending. Late replies and reads from the retired session cannot restore its instances.
- A clip matching its known or recovered instance is on air on that player. Its clock reads the Bridge's position, duration, pause and loop. Changes in time alone do not change ownership. A valid empty reading clears the player row. A held file that no current cue owns is never inferred from its filename. When it supplants a known cue in the same session, the old row says `replaced` and loses transport authority. A Bridge restart cannot attest to the earlier instance.
- An action in flight excludes observations of its player while it settles. An observation begun before that action, or while it was pending, cannot later restore ownership after an unknown outcome. Clear uncertain ownership and require a newly issued, valid observation or another accepted action. A stale success cannot supersede later admitted evidence. The two players keep separate generation and pending-action fences. If the item's configured player changed while it was live, Take waits for an explicit guarded Out on its captured old player. An action cannot implicitly send to another player under the current player's turn.
- Out, Pause and Resume by an owned vMix cue act only on the exact instance still held in the last validated vMix XML in the Bridge's serialized turn. Recheck after async setup or Resume file checks before sending a function. Guarded Out rechecks again after Pause before clearing the list. A confirmed change stops the remaining functions, and a partial action follows the existing uncertain-outcome handling. vMix can still be changed from its native controls after that XML. Guards apply equally to an accepted Take and a recovered row. Use a new guarded transport capability for V5 Out, Pause and Resume, including All out. Its wire forms must be refused by an older Bridge. The released 0.11.0 still asks the operator to update for media. A staged older media Bridge can be read for conclusive presentation. Its ambiguous `other` row cannot grant authority, replace a cue, or clear one. The new Bridge's conclusive foreign row can mark a cue replaced. Studio refuses V5 transport on a staged older Bridge with an Update message, without retrying as an older verb. Older command names and the earlier guarded Out remain available for existing clients. A player reading on its own sends no action.
- Bridge `0.12.0` is the next media release after both main and the published `0.11.0`. The current independent `bridgeVersion` and `release-bridge.yml` replace earlier recipes that coupled Bridge and CLI bumps. V5 adds operator notes and incremental Bridge documentation. The exact merge's automatic Windows release and download are independent acceptance checks.

The fresh Rules-first review agreed with corrections. The lines above include its concrete cases for production copies, lexical aliases and retargets, changed player routes, uncertain or ambiguous state, stored cue edits, folder revisions, native interleaving, and shared session order.

## Baseline reproduction

On Windows at the starting SHA, a focused Node harness started the real production Bridge watch with a fake paired Bridge. The current rundown had one vMix movie cue. The Bridge advertised vMix media and was ready to return a valid playing clip at position three of ten seconds. After status and an explicit wake, the watch made zero player reads and ownership and timing were empty. The assertion that an eligible vMix cue player is read failed. No vMix device was used.

## Implementation and checks

The existing state poll shares its busy, idle and visibility behavior between CasparCG channels and the vMix player snapshot. Studio builds its ownership match from the live saved production, cue and item, and validates the exact lexical name against Bridge's current file observation. Each player has separate command admission and timing. A Bridge restart retires the old process for both. The established CasparCG clock and OBS routes are preserved.

The maintained clock and cue journeys exercise vMix and CasparCG together. The focused Node suites cover malformed and ambiguous rows, exact scope including same-path rebinds, old and pending action replies, pairing and folder changes, and guarded player commands. The fake vMix TCP checks cover alias retargets, malformed XML without identity loss, and a native replacement between Pause and clearing the list. No operator vMix process or mixer was used.

The first Windows browser job `j-5252` passed 44 of 46 cases and found an unscoped overlay validation error and a stale expected wire form in the test. Job `j-5253` verified the clock journey and showed that the pre-existing pairing regression needed to isolate the late reply from the new fresh-read recovery. ## First implementation review

The independent review of `7571f1dea9f67d86d1fcc80138cda2c02ad42d62` found three product defects and one test gap. A matching path and list could mask a nonlooping rewind during guarded Pause or Resume. A malformed native playback state could look valid. ## Reassessment of player evidence

The fresh full review of `462500539ab06b3d01068976b0302d9fe01de008` and a separate read-only reassessment found a repeated continuity rule. Before an initial or later guarded transport sends a function, conclusive missing, foreign or changed native input retires the saved occurrence. Restoring a previously missing native input therefore cannot claim the former Take. An unreadable XML state, impossible position or conflicting setup leaves the previous evidence alone. The native list may be empty with its own Loop setting or index zero or one. Its wire row has no playback flags. A completed clip or zero-duration still remains observable without inventing a timing sample.

The same media-kind rules now govern player rows and file aliases on both ends. The Studio keeps safe presentation from the staged legacy format and normalizes leftover empty input settings. Current rows with contradictory position, source, producer, occupancy or identity are unavailable. Successful V5 guard replies need a positive generation, the expected instance for Pause or Resume and none for Out. They also name the expected Bridge session. A contradictory dispatched result follows the existing unknown-outcome rule.

Windows regressions derive the expected cases from the observable state: removing and restoring an input, rewinding an unchanged nonlooping list during a guarded action, out-of-range XML followed by a valid read, a completed clip, zero-duration still, retained native empty Loop, and malformed current wire replies. The held-stale browser case remains in the same clock journey.

## Current and staged player readings

The full review of `23a18e6a8df72fd825187e94ca3819ace36b5e16` and the round-cap reassessment confirmed two remaining product defects. A Bridge advertising the guarded transport could still receive the older envelope's optional fields. An empty native list with positive time could also look conclusive and retire the prior occurrence.

The watch now binds player reads to the existing ordered health evidence. The current and staged contracts have separate poll lifetimes and a capability switch away and back retires an earlier reply even with no visible render in between. Identical health refreshes retain the pending read. A current reply proves each empty or foreign row with its occupancy field, and an instance with the lexical media name. An older canonical filename can update a known instance's timing without recovering a cue. Native empty XML requires position and duration both zero. An unavailable reading changes no player authority. A conclusively empty player retires the instance. Temporarily changing the media root cannot attest to a file outside it, while restoring the root can attest to the same native occurrence if the Bridge still observes it.

A separate Windows and GitHub typecheck found that the shared extension helper used a method outside Studio's configured TypeScript library. Indexed access now selects the same filename in both mirrored protocol sources.

## Completed playback and the clip clock

The full review of `6ac9fafdf68b8555f280b2401edfaba675be686c` reproduced a finished native clip showing a moving loop while Loop was still enabled. At 3.8 seconds of a 4-second file, a completed clip without Loop also showed a moving final countdown. The grouped reassessment confirmed that native completion is independent of the reported position and Loop setting.

Bridge now reports completion on the selected media row and keeps both values. A known duration gives zero time remaining on the rundown row. Holding starts at the first explicit completed observation and keeps that start while the same instance remains completed. A still or an unavailable duration supplies no new countdown. A genuine Pause or running Loop keeps its existing meaning. A changed state, instance or accepted transport clears the completed clock. After a Resume, the clock waits for the next player position before showing a remaining time.
