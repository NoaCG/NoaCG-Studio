# Fix #2572 evidence: a change elsewhere in the rundown never discards the cue being typed

Scoped fix inside the live-publishing run (#2361), before phase 8's AC-6 lands: AC-6's own
five-person check meets it (an editor typed `#9`, the team's record and every page kept `#8`), and
the 10-page run lost the last text of up to 6 of 7 editors.
Review class: Risky (other tabs and writers; the cue draft's save; the undo history).
Previous verified `main`: 7be4b007272148295c8e6dffcbd32344c772f39b. Revert: `git revert -m 1 <this pull
request's merge commit>`; nothing persisted changed, so no data step goes with it.

## Cause

`src/components/home/useRundownHistory.ts` keeps the production page's undo history. When the
rundown changes elsewhere (another tab's save, a teammate's save the page adopts), the history can
no longer be trusted, so it is cleared with the note "changed elsewhere". Two places do that, and
both also throw away the cue being typed:

- `reconcile`, run on every team state change and every `spx-data-changed`, finds the rundown no
  longer equal to the open typing group's slice (or to an unconfirmed team edit) and calls
  `invalidate()`, which calls `cancelDraft()`: the typed text leaves the screen, nothing is unsent,
  and the next save sends the old text.
- `perform`, the draft's own queued write, finds the same mismatch, calls `invalidate()` and returns
  without writing. A draft write queued before another invalidation is dropped by the queue itself
  (its epoch moved), so the text is never written.

A teammate editing any other cue is enough. The more people edit, the more often it happens.

Reproduced on `main` by the new test in `e2e/rundown-history.spec.ts` (below): "Typed here" reverts
to "Alpha" when another cue is renamed elsewhere.

## Rules (observable; stated before the code)

- **D1.** A change made elsewhere (another tab, a teammate) that leaves the cue being typed exactly
  as it was never discards the typed text: it stays on screen and is saved over the new rundown,
  changing only that cue's typed fields; every other cue keeps the change made elsewhere.
- **D2.** Such a change still clears the undo history with the same note ("changed elsewhere"), as
  today.
- **D3.** A change made elsewhere to the cue being typed itself (its label, note or values, or its
  removal) is handled as today: the typed text is discarded and the note says the rundown changed.
  Which of two texts typed into one cue should win is the owner's to decide (O10); this fix keeps
  today's answer.
- **D4.** Undo and redo still discard the cue being typed first, as today.
- **D5.** The typed text reaches the record on its usual idle save even when a change elsewhere
  (D1) arrived while that save waited its turn in the page's write queue.
- **D6.** Nothing else changes: every other write (Delete, Duplicate, a move, a restore) still
  refuses and clears the history when the rundown changed under it.

## Durable check

`e2e/rundown-history.spec.ts`, "a change elsewhere in the rundown never discards the cue being
typed (#2572)": the cue is typed, then a different cue is renamed elsewhere before its idle save
(D1, D2), and again after the save was queued (D5). A second case renames the typed cue itself
elsewhere and expects today's discard (D3). It fails on `main`.
