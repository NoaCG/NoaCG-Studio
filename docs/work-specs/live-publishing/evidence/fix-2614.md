# Fix #2614 evidence: the team record without its designs

Scoped fix inside the live-publishing run (#2361), cause 1 of the phase 9 load diagnosis
(`phase-9-load-diagnosis.md`): every team save sent and rewrote the whole record, every graphic's
template included. Design: `../designs/G5-team-record.md` (Rules R1 to R16, graded A by a
Rules-first `/so` before any code; PR #2626). Review class: Risky (a migration, a persisted format,
the old and new page rules).

## What changed

- **Migration `0123_team_designs.sql`** (live-path: a guard trigger on `control_shows`). A table
  `team_production_designs` stores each design once per production under the SHA-256 of its stored
  text; `team_productions.doc_form` (null whole, 1 split) is set by a trigger from the content
  alone, which also refuses mixed content, a `template` in a split record and a name the
  production does not hold. A restrictive read policy, and new checks in `team_production_save`
  and `team_production_patch`, refuse an unmarked (older) page "Reload this page to edit" on a
  split row before answering. `team_production_store` stores a split record. `team_designs_state`
  answers installed, mark and switch. `team_production_unsplit` is the revert. The guard on
  `control_shows` refuses an older page's publish, unpublish or delete of a split production; its
  Takes, reports, heartbeats and a source's Pause pass. Nothing is split while the `team_designs`
  switch is off (absent = off). No stored record is rewritten by the migration.
- **Pages** (`src/backend/teamDesigns.ts`, `src/backend/teamProductions.ts`,
  `src/backend/supabase.ts`). Every REST request carries `x-noacg-team-designs: 1`. Every record a
  page receives is made whole before anything sees it; designs are read only when the page holds no
  copy (at most 8 per call). With the server installed, the switch on and Web Crypto present, a save
  puts only designs the page has no name for (at most 1 MB per call) and stores the split record;
  else it saves whole as before. The `Show` in memory, the merge, Undo and publishing are unchanged.
- **Connector tools** (`api/_lib/me/connectorTools.ts`): a split record's design fields are read
  from the designs table, so `noacg_library` answers as before.

## Apply and revert

- **Apply** (the coordinator; live-path, quiet window): `npm run db:push -- --live 0123`, or the
  next quiet post-land run. Before the app lands, a CORS preflight to the production REST address
  naming `x-noacg-team-designs` must answer it allowed (G5 section 7 step 1). The app works without
  the migration (it reads whole and saves whole until `team_designs_state` answers).
- **Switch on** (the owner's step, production): after a new page on production reports
  `team_designs_state().mark = true`, operators have reloaded, nothing on air:
  `insert into public.system_settings (key, value) values ('team_designs', '{"on": true}') on conflict (key) do update set value = excluded.value`.
- **Switch off**, instantly: `update public.system_settings set value = '{"on": false}' where key = 'team_designs'`.
- **Revert**: switch off and wait 30 s; as the service role, for each id in
  `select id from public.team_productions where doc_form is not null`, run
  `select public.team_production_unsplit(id)`; then a migration (quiet window,
  `--allow NNNN --live NNNN`) that raises while any `doc_form` is set and drops the guard trigger and
  its functions, the policy, the form trigger, the new functions and `team_production_designs`, keeps
  the column `doc_form`, and restores 0117's `team_production_save` and 0119's
  `team_production_patch`.
