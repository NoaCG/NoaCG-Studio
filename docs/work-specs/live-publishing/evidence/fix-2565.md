# Fix #2565 evidence: an edit made while the page reads teammates' changes is kept

Scoped fix inside the live-publishing run (#2361), before phase 8's AC-6 lands: phase 8's
five-person check hits it (an editor typed `#9`, the team's record kept `#7`, on every page).
Review class: Risky (other writers; reload and recovery of a team production's edits).

## Cause

`refreshOnce` in `src/backend/teamProductions.ts` reads the teams, then decides which productions
hold an edit on its way up (`keep`, from `dirty` and `inflight`), then awaits the documents of every
other production whose token moved. An edit made during that await (typing into a cue, preparing a
message) marks its production dirty, but the code after the await still uses the `keep` taken
before it:

- it sets the fetched document and token as that production's base, so the edit's save goes up
  with the newer token and is accepted without a merge;
- it applies the fetched record over the page's record (`applyServerTeamShows(records, keep)`), so
  the edit is gone from the page, and the save sends the server's text.

The team read runs on a 15 s poll, on window focus and when the page comes back online, so the
window opens whenever someone clicks into a window and types while a teammate has just saved.

## Rules (observable; stated before the code)

- **F1.** An edit made to a team production while a team read is out stays on the page: the read
  never replaces that production's record.
- **F2.** That production's save is judged against the base and token the edit started from, so a
  teammate's save the read saw is merged with the edit (the existing refusal and merge), never
  written over and never dropped.
- **F3.** A production with no edit during the read takes the read's document, base and token,
  exactly as today.
- **F4.** A production that already held an edit when the read began is handled as today: not read,
  kept as the page has it.
- **F5.** The edit reaches the server: a production left dirty after the read is saved, as today.
- **F6.** Nothing else of the read changes: teams, members, heads, and the removal of productions
  the read no longer lists.

## Durable check

`scripts/team-save.test.mjs`, the production module's own `refreshOnce` with the backend stubbed: a
teammate's newer document arrives while an edit is made inside the read's await. It fails without
the fix (the page's record becomes the teammate's and the edit is lost) and passes with it.
