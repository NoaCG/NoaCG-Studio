# Fix #2565 evidence: an edit made while the page reads teammates' changes is kept

Scoped fix landed inside the live-publishing run (run #2361), after phase 8 found it. Row class:
**Risky** (it changes a state rule of the team save in `src/backend/teamProductions.ts`).

## Cause

`refreshOnce` took `keep` (productions with an edit waiting or on its way up) before
`await fetchTeamProductionDocs(stale)`. An edit made during that await marked the production
dirty, but the fetched document and token still became its base, and `applyServerTeamShows`
replaced its local record with the fetched one, because `keep` was the set from before the await.
The typed text left the page's record, and the save that followed sent the server's text with the
new token. The same held for a production that was not being fetched at all: `applyServerTeamShows`
rebuilds every listed record from its base unless it is in `keep`, so any teammate save elsewhere
opened the window for every production on the page.

## Rules (observable; stated for a Risky row before coding)

- **R1, an edit made during the read is kept.** When the document fetch answers, a production, fetched
  or not, that has an edit waiting or on its way up at that moment (dirty or in flight), or had one
  when `keep` was taken (after the heads read and the outbox restore), keeps both its base and
  token and its local record exactly as they are. Its save goes up with the old token; a teammate's newer save refuses it, and that refusal merges the two.
- **R2, a change of this tab during the read is not undone.** "The read" is the whole pass: the
  heads list and the document fetch. A production whose known server entry is not the one held
  when the pass began (replaced, added or removed: a save confirmed or refused,
  a rundown undo, a move or a delete meanwhile) keeps that entry and its local record; the fetched
  row, read before or around that change, is not adopted.
- **R3, nothing else changes.** Every other fetched row is adopted as before: its document and
  token become the base and its local record is replaced.
- **R4, a skipped production is never stuck.** A production skipped under R1 or R2 is fetched
  again on the next pass in which it has no edit owed and its head token differs from the known
  one, so a teammate's change still reaches the page.

## Change

`refreshOnce` snapshots the server entries when the pass begins, before the heads read. When it answers, every production that
is dirty or in flight, or whose entry differs from the snapshot (`changed`), joins `keep`: its
fetched row is not adopted and `applyServerTeamShows` leaves its local record. `changed` entries
also skip the unlisted sweep, are passed to `applyServerTeamShows`, and keep their shown head (R5).
The stale test is unchanged, so R4 holds. The snapshot copies a map of one entry per team
production on the page, once per pass.
