## The rule pass

- **Validator rule (D3): reworded.** "Inject the harness validator into every provider call" was
  never true of the raw route: `generateRaw` validates itself and `screenChange` in
  `src/ai/creation.ts` screens its result where the step shows it. The new text says so; the
  demand on every other route is the same, and `scripts/ai-creation.test.mjs` pins the forwarding
  per route. Scope unchanged (`src/components/wizard/ai/**`): adding `src/ai/creation.ts` would
  load the rule into the `src/ai/` chain, which already holds the forwarding guard as a test.
- **Dollar line (D4): no rule change.** `ProPanel.tsx` prints `costUsd` on the Pro result card,
  against `wizard/show-money-result-card-prices-codebase`. The card never renders while the Pro
  door is closed, and AC-14 keeps the Pro code a move, so the line stays. The invariant is right
  as worded; changing it to allow the line would change what it demands. The evidence went onto
  the invariant's record: whoever reopens the door removes the figure in the same change.
- **Retirements: none.** The five Pro rules in `wizard/ai/` (`ask-pro-tier-thing-which-graphic`,
  `branch-pro-ending-size-set-never`, `handle-pro-finding-step-cannot-repair`,
  `offer-pro-tier-only-where-can`, `report-pro-result-card-language-rationale`) govern code the
  owner chose to preserve (section 1.1, decision 2) so it can reopen; retiring them would leave a
  reopening without its guidance. `ai/offer-managed-pro-only-reports-hosted` still holds: the
  conjunction it preserves is the step's written reopen instruction.
