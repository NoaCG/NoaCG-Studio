# Restore canvas transform coverage

## Why and goal

PR #699 quarantined `e2e/editor-canvas-transforms.spec.ts` after CI run
37194062665, job 111412203707, moved the opposite corners during the nested SVG
edge-scale assertion and passed on the same commit when rerun. Reproduce that
failure, fix its cause, and restore the spec to the blocking suite.

## Scope and decisions

Keep every existing assertion and tolerance. Keep retry, gate, timeout, and
quarantine release policies unchanged. Use the existing preview protocol and
gesture paths; change only the cause demonstrated by reproduction. If the race
does not occur locally, force the suspected window temporarily and compare its
failure signature before accepting a fix.

## Acceptance

- Reproduction fails at the nested SVG opposite-corner assertion, with evidence
  explaining the stale or incorrect geometry responsible.
- Rotation and edge drags still match numeric fields, preserve the opposite edge
  without Alt, preserve one-step undo, and refuse SVG anchor editing visibly.
- Repeated focused runs execute and pass, with no retries or skipped tests.
- The whole restored spec passes, the build passes, and `/check` stamps the
  committed tip before `/queue-merge`.

## Evidence

### Diagnosis and reproduction

- Read [PR #699](https://github.com/NoaCG/NoaCG-Studio/pull/699), the full
  [failed job](https://github.com/NoaCG/NoaCG-Studio/actions/runs/37194062665/job/111412203707),
  and its trace. CI failed the original line 710, column 115: corner 1 was
  `(737.569, 726.702)` instead of `(753.875, 736.841)`. The trace shows Archivo
  being requested again after every stylesheet replacement and text bounds
  changing between the ready and pose replies.
- Five unmodified focused runs passed locally (`j-3267`). Delaying only the
  final undo's Archivo response by 250 ms, then letting subsequent drag loads
  complete normally, reproduced the same opposite-corner assertion (`j-3269`):
  `(754.515, 737.096)` versus `(738.594, 727.475)`. The direction reverses with
  the order of fallback and loaded-font measurements; the roughly 16 by 10 pixel
  signature and failing assertion are the same.
- Replacing `style.textContent` destroys unchanged `@font-face` rules. With
  `font-display: swap`, a ready reply can therefore carry fallback geometry that
  changes when the face loads. Updating changed CSSOM rules in place preserves
  the loaded face during transform drafts, commits, and undo. The authored source
  stays in the template; the runtime retains its last CSS string for base-pose
  invalidation because CSSOM edits do not rewrite the style element's text node.
