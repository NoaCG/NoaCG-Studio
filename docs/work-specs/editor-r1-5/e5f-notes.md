## Rules stated before implementation

1. Both editor Help and Edit send their bounded structured request through Studio's server-owned gateway route. The server alone selects the deployment's managed provider/model and credential. Personal provider/model/fallback/temperature/seed preferences, supplied routing overrides and sealed user-key cookies cannot change either call's route, sampling or payer. An eligible, consenting user can invoke Help and Edit without personal provider configuration or saved keys: availability follows Studio's managed service and applicable access controls. Failures never request personal AI setup. Other surfaces keep their current personal behavior. No new provider, account, paid plan, retention policy or production setting is introduced. Missing/rejected managed credentials refuse honestly, without using a personal key or silently substituting another route.
2. Existing consent precedes either request. Existing authentication, managed-route switches, applicable entitlements, rate limits, request/token/time/attempt bounds and content-free accounting remain authoritative. Configuration presence is not provider validation. An actual hosted connection and reviewed edit/Undo are required for real-provider acceptance; fixtures only prove engineering behavior. Earlier E3 paid calls and consumed allowances stay historical and spent.
3. Help is read-only and has no Apply action. Both calls capture and recheck the current document binding, source/assets revision, selection/playhead and active gesture state. Cancel, close, unmount, mode/document/selection change or newer request invalidates old results, including away-and-back context. Edit preparation is read-only; explicit Apply rechecks context and commits one validated complete batch, or changes nothing. Undo restores the exact pre-apply source/assets/fields; source acceptance and preview readiness remain distinct.
4. A blank-project or blank-graphic door opens usable authoring without a mandatory starter. Existing unsaved-work/recovery guards run before replacing the document. Durable storage confirmation precedes reporting creation or navigating to a saved document. New graphics have independent durable identities, source and history; creation never replaces another graphic or an installed/on-air production copy. Failed storage preserves the existing document and reports failure. Starter selection remains available with recognizable names and actual visual previews.
5. Panel resizing changes editor layout preferences only: no artwork, animation, selection, history or saved source. Pointer and keyboard controls clamp all dividers to reachable bounds at both existing viewports/zoom requirements. Smaller viewports clamp the effective layout without destroying retained preferences; reload retains a valid layout, reset restores defaults. Pointer cancellation/Escape does not leave an active gesture or a stuck capture. Corrupt/old preferences use safe defaults.
6. Whole-graphic positioning/scaling acts on the composition's artwork as one coordinate space, preserving relative positions, existing animation, fields, assets, output canvas dimensions and saved/exported appearance. Supported changes go through the existing atomic editor session/history path and remain editable after save/reopen; Undo/Redo restore exact source. A source without a safely supported artwork root, or with competing transforms/unsupported imports, refuses before any source/history mutation. No destructive rewrite is used merely to enable a control. Existing supported animation controls remain separate from base placement.
7. Only this phase's four corrections are implemented, serially: Studio-managed assistant, blank creation/previews, panel sizing, whole graphic. Each verified step is committed. A confirmed E4-attributable defect stops for coordinator/owner reassessment before editing that defect. Independent production copies and newer-write safety remain unchanged.
