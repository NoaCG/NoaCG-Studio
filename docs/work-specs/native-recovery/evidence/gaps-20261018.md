## Offline fixes and acceptance

These helpers are opt-in receipt guards and a usage reader. They make no provider
calls, restore no remote workspace and enforce no remote ownership lock.

| Criterion | Reproduced defect | Corrected behavior |
| --- | --- | --- |
| Submission binding | Matching action/hash could accept a receipt for another native owner or policy | `reconcileNative` requires provider, session, environment, revision and policy fingerprint on both the persisted intent and observation, including final non-delivery; a rejection carrying an accepted native ID remains unknown |
| Exact cadence admission | Any future due inside the window was eligible even when exact cadence was requested | An explicit `authorization.cadenceMs` requires the encoded `next.dueAt` to equal raw `previous.arrivedAt` plus that positive integer interval; missing arrival, rounding and update-relative drift remain unknown |
| Usage integrity | An interval could add more cached input than total input while lifetime and whole-window totals appeared valid | The Codex reader rejects each impossible cumulative delta instead of reporting the window as observed |

The binding fields are mandatory for reconciliation; callers with old incomplete
intents remain parked. Existing bounded wakes without a cadence requirement retain
their previous behavior. Exact cadence is optional only because bounded re-arm and
exact hourly delivery are different claims: set `cadenceMs=3600000` for the latter.
`dueAt` must describe the actual encoded request, including any serialization change.
Admission still does not establish provider acceptance or actual delivery. A successful
response must be retained and checked; it must never be discarded to manufacture an
uncertain-send case. No production caller is wired to these guards yet.

The three regression cases failed before their fixes. Direct execution of
`scripts/native-recovery-contract.test.mjs` and `scripts/native-recovery-context.test.mjs`
then passed all 18 tests. Fixture results qualify these local checks only.

## Remaining native boundaries

| Gap | Evidence still required before crediting it |
| --- | --- |
| Permission continuation | Supported native inspection of exact policy and pending approval/turn, authorized resolution of that same wait, and the resumed action under equivalent policy. File access and sandbox command grants do not supply this chain. |
| Genuine uncertain send | An actual ambiguous transport outcome, the pre-existing intent/request hash, and exact native reconciliation to acceptance or authoritative final non-delivery. Timeout, silence and an empty catalog cannot authorize replay. |
| Native usage and context (#805) | Exact-owner native counters with a pre-window baseline, loaded instruction/tool context and observed planning turns. Prompt/retrieval bytes remain separate; unavailable counters stay null and no savings claim follows. |
| External reconstruction | Recover the owned revision, spec/evidence hashes, absolute authorization end, waits, unresolved intents and acknowledged PR owner from evidence outside the lost filesystem; then reconcile native tasks and current GitHub state before any dispatch.
