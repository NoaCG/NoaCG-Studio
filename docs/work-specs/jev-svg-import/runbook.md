# SVG plan preparation and start handoff

Uses the existing plan-create and plan-run procedures. Owner accepted the corrected order and
standing automatic block renewal, and authorized preparation/registration/landing. The owner
explicitly forbids opening a project, starting a block, creating the run issue or arming triggers
until “start”. This instruction overrides plan-create's automatic handover. No approval is being
requested again for budget, duration or block renewal.

## Prepared files

- spec.md: sole40-row order and26 product criteria; phases.json copies exact metadata.
- work.json: agreed planning intent and normalized hash, null product convergence review.
- decisions.md: verbatim owner decisions, scope reconciliation and43-to40 mapping.
- readiness.md: current proof, failures and exact pre-start steps.
- preparation/project.draft.json: full phase objects and project policy; no live authorization.
- preparation/state.draft.json: kit fields, common reads, no in-flight work or triggers.
- preparation/run-issue.draft.md: complete public-safe issue body, not posted.
- preparation/start-contract.md: fixed policy and single future start sentence.
- preparation/launch-bindings.json: deterministic population of time/runtime-generated identities.
- preparation/evaluation-environment.md: main-only harness/config/secret/storage/budget contract.
- preparation/corpus-receipt.json: hashes/counts/provenance and restricted holdout commitment.

These draft files deliberately fail live authorization until actual start timestamps exist.
Issue/session/block/wake IDs cannot exist before their real operations; never use invented IDs just
to make validation pass. The actual Claude identity is an unresolved qualification prerequisite,
not a choice silently assigned to a Codex subagent. Preparation registration is in Runnable plans
but explicitly cannot launch. No parallel scheduler, ledger or corpus engine is introduced.

   with the existing project-authorization/plan-kit helpers, never a new launcher. Project ID is
   plan-jev-svg-import- plus the actual start date. Runtime facts come from real tool receipts.

   performs serial admission. Never use another project ID to bypass a stopped project.

no-go leaves it off and continues rows35–40 with deterministic preparation and mocked integration.
