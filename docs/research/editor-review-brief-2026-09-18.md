## Complete scope retained

- Professional permanent canvas, selectable layers, full 2D transforms, editable property
  keys, direct scrub, visible layer bars, Step/Out flags, reverse exits, loops and history.
- Illustrator SVG wizard remains all-inclusive with direct production/export; optional
  Open in editor preserves fields, appearance, font/assets, quiz/timer logic and layout.
- Canvas text/rectangle/ellipse/image tools, typography/layout, groups, bins and real precomps.
- Template gallery and a coordinated starter collection, Home brand kits, overrides and
  fast reliable installation into a production rundown.
- Embedded basic AI and BYOK, existing CLI source round-trip, then full paired MCP editing.
  One mutation registry and readable source; optional Monaco never replaces the canvas.
- Local property loops first; Lottie and gradient/mask/composable effect authoring in R2.
- Existing fields preserved immediately; structured GDD data, arrays/runtime collections
  and live updates in R3. New text defaults editable, with deliberate decorative exceptions.
- OGraf-first interoperability plus SPX/CasparCG/NoaCG playout. Named receiving-host and YLE
  workflow evidence before compatibility claims. No copied Studio scene store/runtime.
- Node editor excluded from R1-R3, with its code, schemas, tests and lessons retained.

## Questions for the independent reviewer

1. Can the simple In/hold/Out task be delivered coherently by R1.1 without a second scene
   model, preserving the wizard and producing the same result in preview and output?
2. Are cue-boundary sampling, layer trimming/cross-cue moves, reverse easing/current-pose
   rebasing and nested transforms precise enough? Identify contradictory or missing rules.
3. Are precomposition ownership, operator field identity, history and preview revision
   contracts maintainable with the current `SpxTemplate`/`NOACG_ANIM` seams?
4. Does any accepted capability disappear between the master plan, mechanisms and E/B
   register? Check templates/brands, AI, live data, Lottie, export and SVG behavior explicitly.
5. Which proposed implementation claims still need evidence before widening a slice?
   Separate blockers from preferences; propose corrections without implementing them.

## Evidence and open decisions

The [baseline](editor-baseline-2026-09-17.md) and
[baseline supplement](editor-design-review-2026-09-17/baseline-supplement.md) retain observed
old-editor failures and limitations. Remaining source/transform, latency, comparative user
and actual-host checks are assigned to slices, not waived. Prototype checks prove only those
local interactions. Actual YLE renderer/version and free-AI launch budget are still unknown.
Studio source/licence research is pinned and retained in the consolidation archive; the
active decision is our own implementation informed by reference behavior, with no imported
third-party helper code in this planning package. Review exact licensing before any reuse.

The latest user authorization permits committing and pushing this package for review.

planning branch does not authorize product changes, merge queue submission or deployment.
