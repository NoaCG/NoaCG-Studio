# Crafting Apps and the NoaCG editor

Research on 2026-10-07. Recommendation: keep NoaCG's source-backed editor and output adapters. Borrow the Craft apps' discoverable command catalog and repeated-drawing behavior. Do not adopt their document engine or UI for the current task. A focused Rust/WASM path kernel remains a credible later option, subject to a task and measured benefit.

This is evidence for [EDITOR_PLAN](../../EDITOR_PLAN.md), not a second roadmap. [Spec](spec.md), [machine-readable observations](evidence.json), and [verification receipt](check.md) accompany it. No product implementation or dependency change was made.

### Source behavior and tests inspected

**VectorCraft:** [tool state machines](https://github.com/storytold/vectorcraft/tree/5cacbe36b33608c8803e03f25a1178354218f9a0/crates/tools/src) separate events from Begin/Preview/Commit/Cancel/Exec actions. Shape pointer-up commits and clears the gesture, without changing the selected tool. Select and Direct Selection separate whole-object from anchor/handle editing; area-text frame reflow is distinct from scaling. Pen history and Escape are deliberately different from NoaCG. Shape click opens a size dialog, while NoaCG's contract supplies a small default shape. Borrow a lifecycle table, not these semantics wholesale.

[Geometry](https://github.com/storytold/vectorcraft/tree/5cacbe36b33608c8803e03f25a1178354218f9a0/crates/geom) uses anchor subpaths with absolute in/out handles and document points. Its `normalize_deg` deliberately maps 720 degrees to 0; that cannot replace NoaCG's turns+degrees animation values. [Path operations](https://github.com/storytold/vectorcraft/tree/5cacbe36b33608c8803e03f25a1178354218f9a0/crates/pathops) depend on its geometry crate, kurbo, linesweeper and thiserror. The tool crate also depends on document, text, color and pathops; it is not a small independent browser kernel. Tests for geometry, gesture/history and multi-document rollback were inspected, not executed.

[SVG import/export](https://github.com/storytold/vectorcraft/tree/5cacbe36b33608c8803e03f25a1178354218f9a0/crates/svg) normalizes into an editable scene and writes a new SVG. In the actual nested fixture, `#headline` becomes `#Headline`, `#parent` becomes `#Transformed_parent`, basic shapes become paths and transforms are baked into coordinates. Live text, image, gradient and mask content remained present, and the frame was inspected, but warnings were empty despite those identity changes. This is useful editable-vector import, not NoaCG's unrelated-source/selector retention. An imported field or animation referring to the old ID would need an explicit mapping and fidelity gate. No HTML/CSS/JS broadcast package round-trip was demonstrated.

**EffectCraft:** [engine registry](https://github.com/storytold/effectcraft/tree/3af4649429de70f4b9b0b66bbee7a6129c457e52/crates/engine/src) carries command IDs, labels, menu/shortcut placement, parameter docs, enablement/refusal and execution. Query commands expose property paths and capabilities. `execute_checked` validates unknown top-level keys before using the ordinary engine handler; `engine.batch` provides rollback/result references and one undo. Its generated JSON schemas derive accepted keys from prose and generally give descriptions rather than complete value types/ranges. NoaCG should use explicit runtime schemas for its bounded operations, not copy that parser or advertise every upstream command.

[Keyframes](https://github.com/storytold/effectcraft/tree/3af4649429de70f4b9b0b66bbee7a6129c457e52/crates/keyframe) implement temporal speed/influence, spatial Bezier and text/value models. Its [measured AE comparison](https://github.com/storytold/effectcraft/blob/3af4649429de70f4b9b0b66bbee7a6129c457e52/docs/fidelity/README.md) reports eight scalar Rotation cases, 168 samples, maximum error below 3e-11 degrees after a fix, against AE 26.3x87/AEsync 2.0.4. This is useful concrete regression evidence, not overall AE parity. The external oracle was not rerun here. Its timing/property model is not a drop-in replacement for NoaCG's ease strings, speed-relative cue time, exact Out splits and interruption behavior.

The [web application](https://github.com/storytold/effectcraft/tree/3af4649429de70f4b9b0b66bbee7a6129c457e52/apps/effectcraft-web) supplies a browser promise API, file table and storage around the same engine/UI. SVG footage is rasterized at requested scale in `crates/media/src/layered.rs`; available conversion commands do not prove retention of original HTML/SVG fields or editable broadcast output. Raster/video/Lottie rendering is a different delivery model.

**FilmCraft:** [automation](https://github.com/storytold/filmcraft/blob/86f3375775258cd7140c36e5b8e3d21ced9ee711/crates/automation/src/server.rs) has discoverable commands, MCP annotations and strict tool wrapper arguments. Command params go through unchanged. `command_batch` stops on error by default and each completed edit remains its own undo step; it is not an atomic NoaCG batch. Native headless and bridged interfaces share commands; read-only preview leaves selection/playhead untouched by contract. Video timelines, ticks, clips and media rendering are useful for future asset research, not current In/Next/Out authoring.

The inspected public APIs do not offer NoaCG's combined expected source/asset revision commit guard. Stable IDs and a reported revision alone do not establish concurrent human/agent safety. Retain NoaCG's existing compare-before-commit behavior and qualify asynchronous receipts, cancellation and lost replies separately.

### Maturity and issue evidence

[VectorCraft's roadmap](https://github.com/storytold/vectorcraft/blob/5cacbe36b33608c8803e03f25a1178354218f9a0/ROADMAP.md) distinguishes broad feature coverage from lower interaction readiness and admits unrerun performance budgets. [FilmCraft's roadmap](https://github.com/storytold/filmcraft/blob/86f3375775258cd7140c36e5b8e3d21ced9ee711/ROADMAP.md) says checklist presence includes approximations, has no overall rendered parity comparison and has thin Windows/Linux runtime coverage. Its browser-shell comments are older than the now-runnable published artifact. EffectCraft's broad self-assessments must be read alongside the narrow measured ease corpus and [gaps](https://github.com/storytold/effectcraft/blob/3af4649429de70f4b9b0b66bbee7a6129c457e52/docs/gaps.md).

Open issue reports include VectorCraft [#361 segment dragging](https://github.com/storytold/vectorcraft/issues/361), EffectCraft [#201 large-comp full preview crash](https://github.com/storytold/effectcraft/issues/201), and FilmCraft [#160 black PNG sequence instead of alpha](https://github.com/storytold/filmcraft/issues/160). These were read, not reproduced, and are not blanket judgments about the software. #361 was filed after the inspected source commit. They justify task-level qualification rather than assuming familiar chrome or command breadth means Illustrator/AE/Premiere behavior.

## Reuse routes

| Route | Decision now | Gain, work and tradeoff |
| --- | --- | --- |
| Behavioral specification and original tests | **Adopt selectively** | Repeated drawing, explicit select/point-edit distinction, area-text reflow vs scale, capability/refusal and command/UI parity cases fit current tasks. Write our own task fixtures; retain NoaCG's cue, cancellation, field and source contracts. Lowest integration cost; strongest immediate benefit. |
| Small TypeScript algorithm port | **Adapt only for a reproduced gap** | Pure geometry such as angle constraints, cubic hit/bounds or snapping can be ported with attribution and original tests. NoaCG already has bounded cubic/affine helpers. Units, turns, parent transforms and unsupported-source behavior need explicit mapping. Do not port an entire tool/document stack to fix tool persistence. |
| Focused Rust/WASM kernel | **Defer to an accepted advanced-path task** | VectorCraft pathops/geom is a plausible Boolean/offset/stroke-outline boundary: path arrays in, path arrays out; no document/history/UI ownership. Qualify compound paths, fill rule, tolerance, determinism, singular transforms, allocation/cancellation, worker fallback and error propagation. Measure cold download/start, transfer cost and representative small/large workloads against a TS option before choosing. No focused kernel was compiled or benchmarked here, so no speed claim is made. |
| Local/headless CLI service | **Adapt the pattern for our shared handlers; defer an external Craft service** | Native MCP proves real discoverable headless authoring. A Craft process would introduce its native scene/project model, install/process/version/file ownership and translation back to NoaCG source. It is not a free substitute for a shared operation API and does not itself solve browser-local editing. No always-on service or new pairing boundary is justified. |
| Larger engine/UI adoption | **Reject for the present R1 goal; revisit only with a new owner decision** | An embedded egui/WASM editor supplies substantial tools but replaces DOM/source semantics, browser font handling, UI/accessibility integration, state/history and deployment costs. VectorCraft's regenerated SVG already changes identities; EffectCraft/FilmCraft render compositions/clips. None proved preserved HTML/CSS/JS, operator schema and live editable SPX/CasparCG/OGraf round-trip. A second editor would leave two histories and cue models to reconcile. |

## Three near-term recommendations

1. **Finish repeated construction first, within the existing R1.2b usability follow-up.** Draw several rectangles, ellipses, text boxes and open/closed Pen paths without reselecting the tool; switch explicitly to Select, then Edit points. Keep completion, draft cancellation, point editing and group navigation separate. Preserve NoaCG's whole-path undo and exact Escape. This closes a reproduced owner blocker without new geometry or engine work.
2. **Qualify the bounded shared command catalog at the start of R1.3b, before model-driven editing.** Expose IDs, explicit schemas, capabilities/refusal reasons and inspect/apply/history receipts over the same existing handlers. Prove one human/agent task with deterministic calls first. The current operations are React-independent but use browser DOM parsing and the UI adapter imports the store; browser-headless parity is not proof of a Node-pure library. Keep a DOM-capable existing bridge initially if needed, and measure/extract only the seam a package CLI task needs. No new scene model, public control port, AI product or automatic live pairing. Paired live-document MCP remains R3.2; model/transport evaluation remains separate.
3. **Close the remaining owner feedback as useful tasks before R1.5, without bundling it into the first correction.** Reproduce linked scale/numeric scrubbing and the layer/property journey on current main; improve only observed gaps. Group review around import/create -> ordinary editing -> editable text/defaults -> animate In/Next/Out -> save/reopen -> rehearsal/export. Keep library/cloud save reliability in its existing ownership. Static-text exposure and wizard exclusions are an explicit acceptance gap to qualify, not an implicit engine-replacement argument. Loops/animated assets stay in their assigned phases; no new Illustrator/AE checklist.

The shared human/agent acceptance task: import the nested text+box SVG through the wizard with one public text field and one excluded static text; inspect capability/IDs; create two shapes and new text; edit the public default without changing live samples; edit supported static wording without silently exposing it; set two position keys and an Out; cancel one draft and reject one stale/unsupported batch; save/reopen; rehearse Take/Next/Out; validate and execute the same saved graphic through existing SPX/CasparCG/OGraf adapters. Compare source patch, identities, history and rendered pose for UI vs semantic calls. No new publish/live command is needed. Unsupported styled/outlined text must stay preserved with an actionable reason. If an explicit static-field-exposure task is authorized later, expose it through both routes using the same field builder and guards.

Read EDITOR_PLAN, the October 6 owner feedback, the current Pen/tool/session source and docs/research/crafting-apps-editor-2026-10-07. Write a bounded spec and load folder rules before editing. Leave the next shared-command task recorded for a fresh session.

Acceptance for that slice:

- Select Rectangle once and draw three objects; repeat for Ellipse and Text. Each creation gives the normal selection/bar/field result and one undo; the tool remains selected. Shift constraints and click-only default behavior remain unchanged.
- Select Pen once, finish an open path with Enter, draw/close another path and draw a curved one. Each completed path is one undo. Escape, pointer cancellation, tool switch, document switch, stale source or playhead change discard only the active uncommitted draft and create no orphan ID/field/history entry.
- Draft cancellation retains the chosen drawing tool when still valid in the current context. Explicit Select switches mode. Edit points operates on the selected existing path rather than starting a new one; leaving it restores a coherent tool state. Entering a group cannot leave an enabled creation tool in a scope where creation is forbidden; returning to Composition makes the state clear. Define that transition in the spec using current contracts, without adding a new permanent tool.
- Save/reopen the resulting graphic and execute its existing outputs. Previous source, field defaults/samples, masks, assets, keys and cue behavior are preserved; refusal is atomic. New checks assert tool persistence directly, since existing helpers reselect Pen before every path and miss this defect.
- Prove those checks fail on the unchanged baseline, then pass after the fix. Existing focused editor tests and required affected/build checks pass. Human judgment follows the team-proven task; no blanket owner acceptance or default switch is implied.
