# Pattern bench — data fields

Generated by NoaCG Studio. Every value this graphic can be given, with the **ID** a playout
client sends it under. `f0`, `f1`, … are those ids: they are what travels on the wire, and
the Field column is what each one means.

| ID | Field | Type | Default value |
|---|---|---|---|
| `f0` | Name | text | `Anna Virtanen` |
| `f1` | Place | text | _(empty)_ |
| `f2` | Score | number | `0` |
| `f3` | Timer seconds | text (hidden in the operator UI) | `30` |
| `f4` | Final word | text (hidden in the operator UI) | `FINAL` |

- `f3` is hidden on the operator page but still carries a value (a duration, a setting).
- `f4` is hidden on the operator page but still carries a value (a duration, a setting).

These ids are the keys of the OGraf data object — the same names the manifest schema declares, and what `updateAction({ data })` carries.

## Sending values

JSON (SPX, most CasparCG clients, the bundled control panel):

    {"f0": "Anna Virtanen", "f1": "…", "f2": "0", "f3": "30"}

CasparCG classic XML (`componentData`) — the same fields, same ids:

    <templateData>
      <componentData id="f0"><data id="text" value="Anna Virtanen" /></componentData>
      <componentData id="f1"><data id="text" value="…" /></componentData>
      <componentData id="f2"><data id="text" value="0" /></componentData>
      <componentData id="f3"><data id="text" value="30" /></componentData>
    </templateData>

Values are set with the template's `update()`; `play()`, `next()` and `stop()` run it.
Sending a field again while the graphic is on air updates it in place.
