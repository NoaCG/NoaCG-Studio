This graphic has **2 steps**: after Play, each Continue (SPX) / `CG … NEXT` (CasparCG) reveals the next one.

These ids are the keys of the OGraf data object — the same names the manifest schema declares, and what `updateAction({ data })` carries.

## Sending values

JSON (SPX, most CasparCG clients, the bundled control panel):

    {"f0": "Which planet is known as the Red Planet?", "f1": "Venus", "f2": "Mars", "f3": "Jupiter"}

CasparCG classic XML (`componentData`) — the same fields, same ids:

    <templateData>
      <componentData id="f0"><data id="text" value="Which planet is known as the Red Planet?" /></componentData>
      <componentData id="f1"><data id="text" value="Venus" /></componentData>
      <componentData id="f2"><data id="text" value="Mars" /></componentData>
      <componentData id="f3"><data id="text" value="Jupiter" /></componentData>
    </templateData>

Values are set with the template's `update()`; `play()`, `next()` and `stop()` run it.
Sending a field again while the graphic is on air updates it in place.
