# Re-measured 2026-09-07, after `src/blocks` migrated

The seventh area to compile, and the third read under
`docs/backlog/are-the-big-contracts-still-worth-loading.md`, which asks not only "is this paragraph
true" but "is it still worth anybody's first tokens". `src/blocks/AGENTS.md` was the largest
hand-written contract left once `src/ai` had gone.

| Metric | Before this row | After |
|---|---|---|
| Contract corpus | 484,062 B / 102 files | **472,995 B / 101** |
| Hand-written bytes | 375,941 B / 96 files | **335,070 B / 94** |
| Generated bytes | 108,121 B / 6 | **137,925 B / 7** |
| `src/blocks/AGENTS.md` | 40,894 B | **29,804 B** |
| Its chain (root + this file) | 56,387 B used, 53,613 free | **45,236 B used, 64,764 free** |
| This area's compiled rules | - | **35,677 B across 26 scoped files** |

Bytes are LF, the form git stores, and the "before" column is `origin/main` at the moment this row
merged it - after `src/ai` and the root contract, both of which landed while this was running. The
corpus shrank by 11,067 while this area's compiled rules added 35,677, and that trade is the point
of the row rather than a cost of it: a record is written once and loaded by nobody, a rule loads
only beside the file it names, and what used to be paid for on every visit to the directory is now
paid for by the visit that needs it.

## What a session actually pays now

For Codex, which reads `AGENTS.md` directly, the saving is 11,151 bytes off the one chain that loads
this file. `src/blocks` is flat - twenty-three modules, no subdirectory - so unlike `src/components`
there is no multiplier here; that chain simply went from 51% of the byte budget to 41%.

For Claude Code the shape of the cost changed rather than only its size. Opening any file under
`src/blocks` used to load the whole 40,894-byte contract through the directory's `CLAUDE.md`. It now
loads `.claude/rules/src-blocks.md` - **904 bytes, two rules** that genuinely bind every module -
and the rest arrives with the file it names. Sixty-five of the sixty-nine rules name exactly one
file and three name two, so a session editing `assetOps.ts` pays 913 bytes for that module's rules
rather than 40,894 for everybody's. The area's rules compile to twenty-six scoped files holding
35,677 bytes between them, and the two largest - `animData.ts` at 3,909 and `designLayout.ts` at
3,446 - are still an order of magnitude under what the whole contract used to cost. (Two further
`src-blocks-*` files come from the root row's rules, not this one.)

## The three outcomes

**69 rules written - 24 invariants, 11 traps, 34 rules. 3 claims found false. 13 units true but not
migrated.** The ratio the backlog note asked for is 5.3 rules kept per unit retired, the densest
area read so far and by a wide margin: `src/components` retired about a sixth of itself, this file
about a fifteenth.

### False - checked against the code, not migrated as written

1. **"The stub applies `fullscreen` and nothing else, so an entry here is only as alive as its
   callers."** `StubProvider.modify` in `src/ai/stubProvider.ts` reaches eight block ids through a
   regex table - `css-fade`, `css-slide`, `gsap-pulse`, `text-field`, `lower-third`, `fullscreen`,
   `bug`, `logo` - and `generate` applies `fullscreen` besides. Taken at its word the sentence
   licenses deleting seven live entries, under a rule in the very next line that says an unreachable
   block is deleted rather than repaired. The rule survives; the reachability claim is replaced by
   "read `stubProvider.ts` before calling an entry dead".

   It also hid a real defect. There is no block with the id `lower-third` - the lower-third entries
   are `lt-name-title`, `lt-name` and `lt-title` - so `block('lower-third')` returns `undefined`,
   and the non-null assertion in `stubProvider.ts` throws the moment an offline prompt says "lower
   third". Nobody had looked, because the contract said only one id was ever reached. `src/ai`
   belongs to another session and is not touched here; the fix is filed as its own task.

2. **"Fixed contracts (scoreboard cells, quiz rows) and data-driven categories (hidden textarea
   sources) fail the gate and keep the definition-only add."** There is no definition-only add.
   `SampleDataPanel.addField` tries `addPlacedLine` / `addPlacedImageSlot`, then `addCatalogLine`,
   and REFUSES with the reason when none of them can land a real element - a field nothing on screen
   answers is exactly the defect `scripts/field-coverage.mjs` exists to catch. The same sentence
   appears again in the `designLayout.ts` section ("they return null off-shape so the caller falls
   back to the definition-only add"), and twice more in the doc comments of `blocks/edit.ts` and
   `blocks/designLayout.ts`, which this change corrects.

   `src/components/AGENTS.md` carried the claim too and it was caught there a day earlier. Two
   contracts and two doc comments describing the same removed fallback, none of them updated when it
   went, is the argument for scope: one rule, in one place, reached by every file it binds.

3. **"presetRegistry.ts ... Two callers, one shape."** There are three. Besides `presetApply` and
   `LegacyTimeline`'s start-over, `exampleWithAuthoringRegion` in `src/ai/claudeProvider.ts` calls
   `emitPresetRegion` to put a preset's authored choreography into the model's worked example. That
   is the caller most worth naming: the worked example is the motion the model is asked to ship, so
   changing a preset's emitter changes what every generated graphic imitates. The rule names all
   three.

### True, but no longer worth loading - the owner decides these

Not deleted: all thirteen are in
`contracts/records/blocks/2026-09-07-the-contract-this-replaced.md` verbatim, along with everything
else the file said.

**Six of them are history, and that is this file's pattern.** Where `src/components` had become an
index for the contracts beneath it, this one had become a changelog for its own refactors.

- **The Phase 8 inventory** - that the roughly 2,000-line literal-patch layer is DELETED, naming
  `animPatch.ts`, timelineModel's `splitTween` / `patchTweenTiming` / `patchStep*` / `insertPart*` /
  `setObj*`, and `TimelineView.tsx`. Every file in the list is gone. A reader cannot act on the
  absence of a module, and `timelineModel.ts`'s own header already says which patchers left it.
- **The 33-test classic-strip suite** it replaced, and that every capability it covered has an
  equivalent on the step timeline. The equivalence was checked once; `e2e/timeline-v2.spec.ts` is
  what holds it now.
- **The countdown autopsy** - that the block went on 2026-08-29 and was wrong three ways at once: a
  per-tick counter that drifted late under load and lost minutes in a background tab, a duration
  read once and ignored on every later Update, and an inline `display:none` the entrance reset
  clears. The rule it produced is migrated; the autopsy is its evidence.
- **stepAssign's three old code paths** - two legacy re-emits and a literal array patch. Now the
  record behind the rule that says there is one.
- **The heading `presetRegistry.ts - the preset library (what is left of animPatch)`**, which
  identifies a live module by a dead one.
- **The plan-phase labels** - "Phase 4", "Phase 8 (SHIPPED)" - through `machineEdit`, `timelineLens`
  and the legacy section. The phases shipped, and the docs they number are still linked from the
  rules that need them.

The rest:

- **The preamble's loading mechanics** - that Codex reads this file directly and Claude through a
  `CLAUDE.md` import, plus "Keep it accurate". The compiler writes the header now, and which files
  load together is measured by `check:shared-instructions` rather than described by each area.
- **The pointer to root non-negotiables 1, 2 and 5.** The root `AGENTS.md` is first in every chain
  that reaches this file, so it has already been read by the time this one is.
- **The `cssVars.ts` placement note** - that it lives in `src/model/` because the kernel's
  `packets.ts` reads it, "and the rules below bind it there". A rule's `scope` says that now, and
  the compiler puts the rule where the scope points.
- **The `contrastRatio` cross-pointer** to `src/components/AGENTS.md` for why the UI must not turn
  an advisory ratio into a verdict. A pointer is pure overhead in a file every session in the area
  reads: Claude loads that rule by scope when the component is opened, and the root contract already
  tells Codex to read an area's contract before editing it.
- **The `cssPaintsWith` catalog measurements** - 11 designs never reading `--accent`, 97 never
  `--panel-bg`, 126 never `--text-dim`, measured 2026-09-02, and the owner's 2026-08-28 bug behind
  them. Evidence, and `cssVars.ts`'s own doc comment carries the same numbers beside the function.
- **"which the affected-spec map reaches from this file"** - a contract describing its own position
  in `scripts/e2e-affected.mjs`. That map is computed, not remembered.
- **The dock picking its editing surface from the CODE rather than the category.**
  `src/components/timeline/AGENTS.md` says it at `TimelineDock`, where the choice is written.

## Two rules that Codex now reaches only through prose

`blocks/round-trip-colour-alpha-through-which` and `blocks/decides-which-style-controls-exist-all`
scope to `src/model/cssVars.ts`, because that is where `parseCssColor`, `toHex` and `cssPaintsWith`
live and the old contract said so explicitly. `src/model` is not a migrated directory, so the
compiler writes them into no nested `AGENTS.md` and `--report` lists them - which is the designed
behaviour, not a defect: inventing `src/model/AGENTS.md` from this row would put a file in a
position many chains load from. Claude Code loads both correctly, from
`.claude/rules/src-model-cssvars.md`, the moment `cssVars.ts` is opened. `src/model/AGENTS.md`'s own
pointer, which used to send the reader to `src/blocks/AGENTS.md` for the colour doctrine, now names
`npm run rules -- src/model/cssVars.ts` instead, which answers for both harnesses.

## What the contract did not cover at all

Three modules have no paragraph in the file and therefore no rule from this row: `behaviourData.ts`
(the behaviour binding table, format version 1), `designFields.ts` (the one composition of
`addPlacedLine` + `setLineTextStyle` + `setLineFit` that three producers share) and
`layerTimeline.ts` ("create timeline from layer"). Each carries a substantial header comment, so the
knowledge exists; it just never reached the contract. That is the opposite failure from the one the
backlog note is about, and it is worth saying out loud: a hand-written contract goes stale in both
directions, and only one of those directions leaves a trace.

## What this says about the question

Two areas read this way now give two different answers. `src/components` grew because it took on the
job of explaining the files around it - a sixth of it was a table of contents. `src/blocks` grew
because it kept its own receipts: what a module used to be, which suite it replaced, which phase
shipped when. Neither is the product getting more complicated. Both are the same missing mechanism
seen twice - a contract with nowhere else to put history keeps it inline, and nothing ever removes
it, because removing a true sentence needs an argument that "it is true" cannot answer.

The store answers that structurally. The record is where history goes, the rule is what loads, and
the split is made once, by the person who has just read the paragraph anyway.
