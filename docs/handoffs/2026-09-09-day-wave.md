## The three findings worth more than the rows they came from

**1. Row V's reconciliation was a phantom, and the branch never needed it.** The night handed over one
instruction: reconcile `scripts/e2e-affected.mjs` by hand after merging main, because four rows had
edited it and git would union them silently. V never touched that file. Its only appearance in the
branch's history is the merge commit that took main in; the diff against the fork point is empty and
only row T ever edited it. The `hold` came from `merge-order` measuring candidates against a local
`main` 43 commits stale, which row T had already fixed. **A `hold` verdict older than the fix to the
tool that issued it must be re-measured before it is acted on.**

Also: the handover's recipe said to run `node scripts/e2e-affected.mjs` to read the plan. That script
is a RUNNER - bare, it started Playwright and ran all 1297 tests, taking the machine's one browser
slot. `--list` prints the plan.

**2. The subagent-notification rule is neither of the two things this repo has believed.** A re-probe
found that a launched session DOES receive its own subagents' notifications, and that landed in #178
as a flat refutation. Hours later sixteen fan-out reports from two rows arrived in their LAUNCHER,
which is what the refuted claim predicted. A controlled probe settled it and #181 corrected #178:

> **The notification goes to whoever is inside a turn when it fires.** A session that stays in a turn
> gets its own. A session that has ENDED its turn to wait - which is exactly what a session does
> after it fans out - has the report delivered to its launcher.

So the old rule was right about the case that matters and wrong about why; the correction was right
about the mechanism and wrong to generalise from one shape of probe. **The lesson is about probe
design: a probe that exercises one path measures that path.** That claim's `reprobe` field now names
both shapes and says they must be run as a pair.

**3. The union hazard the night warned about, caught live in a different file.** Merging main into row
E produced NO conflict in `scripts/wave-plan-check.mjs` and a file that could not parse. Rows E and F
had each introduced a binding called `candidates` in one function - a parameter holding the weekly
review's rows, and a local holding the plan's own candidates table. Two different lists, one name,
merged clean.

**The syntax error was luck.** In another ordering it would have compiled and
`candidateProblems(candidates, ...)` would have silently read the plan's table instead of the rows it
exists to enforce: a gate that passes while measuring the wrong thing, which is the failure that gate
was built to prevent. The local is now `candidatesTable`. The test file's conflict was the same shape
and had truncated one side mid-test; both blocks are kept.

## What the delegation channel actually needed

Codex was left idle all night and the ledger read zero. The routing step deserved some of that blame
and not all of it: **a row routed there under the standard recipe would have failed at its first
command.**

> **A delegation's writable root is the LAUNCHING SESSION'S WORKING DIRECTORY.** Not the path in the
> prompt, not a worktree prepared in advance, not the repository. Reads are unrestricted.

Two attempts failed on that before the third worked, and both failures are recorded as
`unusable / cause: prompt` - our invocation, not the model, which is what keeps pool quality honest.
The shape that works is to delegate from the row that owns the work, because that session is already
sitting in the right directory. A second limit found the same way: **"run no git" and `npm run build`
cannot both be asked of a delegate**, because twelve gates here shell out to git and all twelve fail
for a reason that says nothing about the code. The delegate runs the focused tests; the caller runs
the build.
